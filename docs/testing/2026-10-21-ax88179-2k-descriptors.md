# AX88179 Windows 2000 guest descriptor diagnostic, 2026-10-21

**Result:** the read-only hub diagnostic succeeded without an AX function
driver, but the guest descriptors do **not** demonstrate conversion to a
valid USB2 configuration. QEMU reported 480 Mb/s on its EHCI port while
the guest still read `bcdUSB=0300`, 1024-byte bulk endpoints and SuperSpeed
endpoint companions. No networking or AX driver installation was tested.

## Original helper and source boundary

`src/generic/usbprobe/hubdesc.c`, built by `hbdesc.cmd`, creates an original
Windows 2000-compatible `HUBDESC.EXE`. It uses SetupAPI enumeration of
`GUID_CLASS_USBHUB` and the published `ntddk/inc/usbioctl.h` declarations.
Only the following USB hub operations are issued:

- `IOCTL_USB_GET_NODE_INFORMATION` to bound port enumeration;
- `IOCTL_USB_GET_NODE_CONNECTION_INFORMATION` to find the exact target
  VID/PID `0B95:1790` from cached enumeration metadata;
- `IOCTL_USB_GET_DESCRIPTOR_FROM_NODE_CONNECTION` for standard device
  descriptor index zero and configuration descriptor index zero, only
  after the target identity matched.

The relevant published API contracts are
[node connection information](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usbioctl/ni-usbioctl-ioctl_usb_get_node_connection_information),
[descriptor retrieval](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usbioctl/ni-usbioctl-ioctl_usb_get_descriptor_from_node_connection),
and [`USB_DESCRIPTOR_REQUEST`](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/usbioctl/ns-usbioctl-_usb_descriptor_request).
This code does not use DDK/WDK sample sources or Microsoft/vendor binary
code/disassembly. No third-party implementation is adapted.

The helper opens hub handles for reading, caps enumeration at 64 hubs and
127 ports per hub, bounds path storage to 4096 bytes and configuration
storage to 4096 bytes, checks returned byte counts and descriptor steps,
and saves only validated device/configuration bytes. Each overlapped hub
IOCTL has a 10-second wait and 5-second cancellation drain; an undrained
request ends the process without reusing pending request storage. That
failure path is defensive and was not triggered or fault-injected here.
It requests no strings (including serial), MAC/EEPROM or vendor controls,
configuration/alternate selection, reset or driver installation. Raw
descriptor string *indices* are retained; string contents are not queried.

`hbdesc.cmd` builds `/W3 /WX /MT` with the named VC6 toolchain and the old
published USB declarations, linking SetupAPI/user32. The ordinary guest
run verifies loading and actual IOCTL operation; it is not a complete
malformed-driver or cancellation test. Output files are written beside the
EXE. A final source-only path-truncation check was tightened after the run
and rebuilt; the captured run used the executable hash recorded below.

## Observed descriptor mismatch and scope

| Property | Physical host capture | Windows 2000 guest capture |
|---|---|---|
| Connection speed observation | libusb enum 4, SuperSpeed | HMP reports 480 Mb/s; old hub IOCTL cannot independently distinguish full/high speed |
| `bcdUSB` | `0300` | `0300` |
| Device byte 7, `bMaxPacketSize0` | `09` | `40` (64) |
| Configuration length | 57 | 57 |
| Configuration byte 7, `bmAttributes` | `A0` | `80` |
| Bulk IN `82`, OUT `03` maximum | 1024 | 1024 |
| SuperSpeed endpoint companions | Present | Still present at offsets 25, 38, 51 |

The listed byte-7 differences are the **only** byte differences in the
respective device/configuration blobs. The descriptor set is partially
modified by the virtualization path, but retains SuperSpeed configuration
properties incompatible with treating it as a proven USB2 bulk endpoint
set. Neither the HMP speed label nor `LowSpeed=0` proves suitable high-speed
descriptors. The old connection IOCTL reports only low/non-low speed; it
does not provide the extended speed enum.

A later working legacy-OS path therefore needs actual USB2 descriptor
negotiation or a separately verified virtualization solution. A physical
USB2 connection would require the owner's action. Do not patch the saved
descriptors to 512 bytes and call that hardware validation. The observed
Windows 2000 cached connection and successful standard descriptor reads
establish arrival/readability, not driver binding, endpoint configuration,
PHY/MAC setup, Ethernet traffic or working EHCI data transfers.
