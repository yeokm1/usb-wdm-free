## Portable framing core and licence

`src/net/ax88179/axframe.c/.h` adapts RX/TX framing semantics from Linux's
`ax88179_rx_fixup()` and `ax88179_tx_fixup()`, keeping ASIX copyright and
`GPL-2.0-or-later` SPDX notices. Each file has a row in `NOTICE.md`.
The bounds-first, caller-buffer implementation and its tests are written
for this repository; Linux SKB/usbnet/kernel infrastructure is not copied
or required. No Microsoft/vendor binary code, disassembly or DDK/WDK sample
was used.

RX checks the trailer's header count and metadata offset, bounded metadata
array and every padded frame extent before making **any** callback. A
malformed late metadata entry therefore cannot cause partial delivery of
earlier frames from the same aggregate. It understands zero-length dummy
metadata, 8-byte per-frame alignment and the 2-byte IP-alignment pseudo
header; callback length excludes that prefix and alignment padding.
CRC/drop/runt/over-limit frames are omitted and counted. Checksum-error
bits are reported without claiming hardware-verified checksums.

Conservative parser limits are 65536 aggregate bytes, 2048 metadata entries,
8-byte-aligned metadata offset and at most seven final alignment bytes.
Nonzero frame extents must consume the entire data region. A firmware
format outside these rules is rejected, not guessed. Caller-provided
`maxFrame` is restricted to 14..8189 by the wire field and safety policy;
**8189 is not a hardware jumbo-frame claim**. The old product brief describes
a smaller hardware jumbo capability. The tests use a normal 1518-byte
budget. Hardware setup must choose its demonstrated MTU, allocation and
RX/FCS mode; the core neither programs a mode nor strips optional forwarded
Ethernet FCS. RX callback/input lifetime and serialization are explicit in
the header; callback reentry or input mutation is outside the contract.

TX emits one ordinary 8-byte device header followed by the caller's frame.
It enables the device padding bits when header plus frame is an exact
multiple of the **actual selected endpoint** packet size. It performs no
TSO, checksum/VLAN offload, USB ZLP, allocation, register programming or
transfer submission. Invalid capacity/length/packet size leaves output
unchanged and `written=0`. Input/output buffers must not overlap.

## Host verification and remaining gates

`src/net/ax88179/frame.cmd` builds with VC6 `/W4 /WX` and runs the host
test. Recorded result: **PASS: 62861 synthetic AX88179
framing/guard/boundary checks**.

Coverage includes two-frame aggregates with dummy headers, an older layout
without dummies, exact prefix/padding removal, CRC and checksum status,
runt/size drops, late malformed metadata with no earlier callback,
guard-page truncations, all-byte single-bit mutations, header-count/offset
bounds and every TX length 14..1518 against endpoint maxima
8/16/32/64/512/1024. TX capacity failures and exact endpoint-multiple flags
are checked independently. These are explicitly synthetic protocol inputs,
not recorded Ethernet/USB traffic from the connected adapter.

Still required: descriptor/function/endpoint binding, vendor register and
PHY/MAC setup, link-state handling, USB transfer/lifetime/power management,
an NDIS front end, actual RX/TX comparison, teardown under failures and
target-OS tests. In particular the existing physical capture is SuperSpeed;
QEMU usb-host/EHCI acceptance and USB2 descriptor negotiation are unproved.
Do not rewrite those descriptors or claim a high-speed path from `bcdUSB`.
No hardware/network/OS pass or release follows from this host test.
