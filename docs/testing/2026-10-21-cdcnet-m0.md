# CDCNET M0, 2026-10-21

An experimental NDIS 5.0/WDM miniport for QEMU's dedicated `usb-net`
device. No release or hardware-support claim. The public class INF and
the shared network core do not exist yet; `CDCTEST.INF` is test-only and
never belongs under `free/`.

## Sources and build

Original GPL-2.0-only code, written from this repository's design and the
installed Windows 2000 DDK declarations (`inc/ddk/ndis.h`, `inc/wdm.h`,
`inc/usbdi.h`, `inc/usb100.h`, `inc/usbioctl.h`). No DDK sample or third-party
driver implementation was read or copied. No NOTICE row is required.

Published references checked:

- [NdisMGetDeviceProperty](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ndis/nf-ndis-ndismgetdeviceproperty),
  plus the 2000 DDK's older declaration and the source references already
  recorded in `docs/design/ethernet.md` section 4.
- [Selecting a USB configuration](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/how-to-select-a-configuration-for-a-usb-device),
  cross-checked against the older URB/interface structures in `usbdi.h`.
  The implementation constructs those structures itself; it calls no
  newer WDK helper or framework.
- [QEMU USB documentation](https://www.qemu.org/docs/master/system/devices/usb)
  identifies the CDC Ethernet/RNDIS device model. Its descriptor facts were
  previously recorded in the Ethernet design; no QEMU implementation code
  is copied into this package.

```
src\net\cdcnet\build.cmd ndis5 free
src\net\cdcnet\build.cmd ndis5 checked
src\net\cdcnet\test.cmd
```

Both kernel build flavours pass with MSVC 6.0 and the 2000 DDK. Each
contains version `0.0.0.1`. Output and records live under
`out/net/cdcnet/ndis5/<flavour>/`. The PE/import gate is a package-local
copy of the repository's own smoke gate. Its allow-list declares intended
imports; it is not target export-table evidence. NDIS 5.1/x64 is not an
implemented build profile yet.

The host test runs the same descriptor-walk function compiled without
the kernel submission code: 107 assertions and 80 single-byte mutations
of an original synthetic ECM descriptor set. Every truncated input ends
at an inaccessible memory page. The fixture is not a capture from QEMU
or real hardware. Missing union slaves and RNDIS-like interfaces are
distinguished from a valid ECM candidate.

## First guest: descriptor-only M0

Windows 2000 Professional SP4 x86, QEMU 11.1.0, Microsoft's in-box UHCI
stack. `usb-net` is Full Speed (12 Mb/s). Headless, no host cursor input:
HMP keys and PNG screen dumps over `127.0.0.1:44340`.

Base: this repository's `vm/w2k.qcow2`. Throwaway overlay:
`E:\usb-wdm-free\wave2\w2kcdc.qcow2`. Stage:
`E:\usb-wdm-free\wave2\w2kcdc-a`. Options:

```
-display none -machine pc,acpi=off -cpu pentium3,-apic -m 256
-vga cirrus -rtc base=localtime -nic none -usb
-netdev user,id=usbnet -device usb-net,netdev=usbnet,id=cdcnet
```

The stage held the first, descriptor-only driver build (before the later
configuration/termination experiment):

```
5CF8C332E81180A965956898FF9F0AA14E443E9A37F66A76BC13B66A24CB6AB2  cdcnet.sys
97F1482370DDB876820211B69C83ABA13195A7389E6B4F0F9D8947739AD7A00F  CDCTEST.INF
```

The Found New Hardware wizard detected "RNDIS/QEMU USB Network Device",
found `A:\CDCTEST.INF`, and installed the unsigned test package after its
signature prompt. Device Manager reported "This device is working
properly" for "CDCNET M0 (QEMU only; traffic disabled)". Screenshot:
`out/net/cdcnet/m0-start.png`.

Successful initialization requires NDIS to return a PDO, FDO and next-lower
object; reads the QEMU device descriptor and both full configuration
descriptors through that lower object; recognizes the RNDIS and ECM
configurations; resolves ECM's union, active data alternate, bulk and
interrupt addresses; and reads its MAC string. Initialization returns
failure if any of these checks fails. This first binary does not select
a configuration or transfer network frames.

HMP `device_del cdcnet` removed the node without a crash. Windows 2000
displayed its expected unsafe-removal warning (NDIS 5.0 has no 5.1
surprise-removal attribute). After dismissing it,
`device_add usb-net,netdev=usbnet,id=cdcnet` produced another unsigned
installation prompt and a new "CDCNET M0 ... #2" node without an error
icon. This is one idle unplug/replug, not a leak/stress or pending-I/O
cancellation test.

## Configuration and termination experiment

The next source version selects the discovered ECM configuration and its
active data alternate, checks returned pipe handles/types/packet sizes,
and sends finite ARP probes to QEMU's isolated gateway/DNS addresses:
64 bytes, a separate OUT ZLP, then 60 bytes. Both payloads use the device's
actual MAC. This is intended to check frame boundary ordering against a
QEMU network capture. NDIS sends still fail and media stays disconnected;
there is no receive pipeline, DHCP or working network adapter yet.

Guest result for this version is pending. A kernel compile is not the
result of the configuration/termination experiment.
