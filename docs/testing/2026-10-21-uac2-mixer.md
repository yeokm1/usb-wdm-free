# Linux-adapted UAC2 Mixer Unit core, 2026-10-21

`src/audio/uac2/uacmix.c`/`.h` now implements portable Mixer Unit matrix
validation, programmable/fixed access discovery and scalar mixer-node request
encoding. This is host-tested code, not a working Windows mixer or a full
UAC2 implementation. The actual USB transport, tested X4 driver, INF and
kernel builds were not changed or rebuilt.

## Reuse and provenance

The substantive reused portion is Linux's row/column, **MSB-first** matrix
bitmap algorithm and its UAC2 two-byte-tail bounds rule. Source:
[`sound/usb/mixer.c`](https://github.com/torvalds/linux/blob/adc218676eef25575469234709c2d87185ca223a/sound/usb/mixer.c),
Linux v6.12 commit `adc218676eef25575469234709c2d87185ca223a`,
`check_matrix_bitmap` (lines575-580) and `mixer_bitmap_overflow`
(lines2147-2174 at inspection). The unchanged ignored reference's SHA256 is
`05d42ff40ea061dc7a0e050d25f6d7a65a3ae4a20f25605e1d7791262165a347`;
the [reference acquisition log](2026-10-21-linux-refs.md) records original
URLs and revision resolution.

Both adapted files retain upstream **GPL-2.0-or-later**, Takashi Iwai's
copyright and the upstream notice identifying borrowed audio.c code by Alan
Cox and Thomas Sailer, with new adaptation attribution added. Each has a
row in [NOTICE.md](../../NOTICE.md). Source is copied/adapted inside this
repository and compiled locally; Linux is not a build or runtime dependency.
No source is fetched by a build.

The adaptation removes ALSA allocation, Linux types, device state and Linux
pointer-walking assumptions. Original additions provide a caller-owned
immutable view, overflow-safe checks before multiplication/pointer arithmetic,
the UAC2 maximum256 nodes, descriptor/tail/padding validation and a request
wrapper using the existing portable `uacctl.c` serializer. This is meaningful
reuse of a specific algorithm and bounds policy, not a claim to have ported
Linux's whole mixer implementation.

The pinned Linux source itself lists unimplemented UAC2 effects, graphical
equalizers, SRC units, proper clock multipliers and other features in its
opening TODO. Reusing its subset cannot satisfy every requested standard
feature automatically. Linux vendor mappings and historical quirks are not
turned into normative class rules by this work.

## Exact specification contract

Official Audio2 September2026 §4.7.2.6 pp.55-57, Figure4-1 p.56,
Table4-11 p.57 and §5.2.5.5.1 p.101 define the additional boundaries:

- The caller resolves every input pin's logical channel count through a
  cycle-checked topology. The helper receives those counts in baSourceID
  order; it cannot prove they correspond to the actual upstream entities.
- Input counts must be1..255 each; their sum and output count must produce
  at most256 nodes. Products and offsets are bounded before memory access.
  Descriptor bLength must exactly cover pins, cluster, matrix and two tail
  bytes. Caller storage may contain later descriptors, which are not read.
- Matrix bits are input-major, output-minor and MSB-first. Unused low bits
  of the final matrix byte must be zero. Tail reserved bits and capability
  bit-pair10 are rejected.
- Matrix Control Number is **zero-based**, `input*outputs+output`, including
  fixed nodes. MCN0 and MCN255 are legal. This is distinct from one-based
  source-selector positions and from Feature Unit channel0/master rules.
- A fixed matrix node remains readable. Only programmable nodes admit
  SET_CUR. `UacMixSetup` emits selector01 and MCN in wValue, entity/interface
  in wIndex, signed16 CUR or scalar RANGE shape. An explicit separate
  capability flag is still required for SET_RANGE. Gain CUR silence0x8000
  is legal; applying control-specific RANGE limits remains caller work.

Remaining work includes actual graph traversal/channel-cluster resolution,
USB execution/recovery, mixer-specific RANGE domain validation, cluster and
status/latency controls, Windows topology/volume properties, multichannel
streams, device changes and physical/simulated mixer testing. No full-spec,
kernel-load or usable mixer claim follows from a parsed bitmap.

## Verification

`src/audio/uac2/mtest.cmd` passes **2,827,584 checks each** with MSVC6 `/Od`
and `/O2` core builds; `/W4 /WX`, unoptimized fixture/assertion harness.
Tests enumerate legal matrix dimensions through256 nodes, every node's MCN,
fixed/programmed GET/SET behavior, response/setup bytes and truncation at
every descriptor offset. Separate single-bit16x16 fixtures compare every
matrix bit against a row/column oracle; malformed sources, counts, padding,
tail permissions and overflow are rejected. Descriptors end at a guard page.

The original control suite, expanded to policy family10/Mixer, passes
**9,613,940 checks each** under both MSVC core modes. An independent GCC16.1.0
x64 build with optimized core **and optimized full harness** also passes
both suites, including `-fsanitize=undefined` in trap-on-error mode. Ordinary
libubsan linking was unavailable; trap mode completed without a trap. This
does not fully reduce the earlier MSVC6 optimized-harness discrepancy
recorded in [the control log](2026-10-21-uac2-controls.md).

For the optional independent audit, run:

```powershell
src/audio/uac2/gtest.ps1 -Compiler <installed-gcc.exe>
```

No download or installation occurs. The actual audit used host MSYS2 GCC16.1.0
at `C:/Users/yeokm1/scoop/apps/msys2/current/mingw64/bin/gcc.exe` with
`-std=c99 -O2 -Wall -Wextra -Werror -Wno-misleading-indentation` and, for the
second run, `-fsanitize=undefined -fsanitize-undefined-trap-on-error`.
Normal package checks retain their named repository-local MSVC6 toolchain;
the optional audit is not a new package dependency. Logs are ignored under
`out/audio/uac2/mixer/`, `control/` and `gcccheck/`.
