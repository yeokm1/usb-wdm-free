# Prepared native-host X4 ISO baseline

This is an original user-mode host diagnostic, **not a project driver or a
WinMM client**. It separates direct host libusb/libusbK ISO behavior from
QEMU and the guest driver. Preparation and mock testing completed, followed
by one controlled physical run recorded below. Further physical execution
requires a newly coordinated X4/quiet window.

Source: `src/audio/uac2/natprobe.py`, `nattest.py`, `natcore.ps1` and the
existing original `uacrate.c/h`. No UAC kernel source or installed C7 image
was changed. There is no vendor/MS driver code inspection, injection,
kernel-driver rebinding or EEPROM write. All transfer code and mock scheduling
are original. The program reads only public descriptors and calls public APIs.

## Bounded experimental policy

Only one `041e:3278` device at actual high speed is accepted. The active
configuration must match the read descriptor; no SET_CONFIGURATION path
exists. The exact profile gate checks AC3, Clock Source33, Selector34's
single source33, AS4alt1 terminal3 stereo Type-I16LE, OUT01 MPS112 interval1,
and explicit feedback83 MPS4 interval4. This is an X4 baseline, not generic
UAC2 support. The existing captured X4 fixture passes; all truncated fixture
prefixes reject.

Interfaces3/4 are explicitly claimed. Original alt and clock are read first;
an already active playback alt is rejected. The original rate must be a
valid supported RANGE value. Only if needed is Clock33 set to48k; it is read
back and Clock Validity checked. Selector34 is read, never written. Alt1 is
selected only after validation. Cleanup drains all callbacks, sets alt0,
restores and verifies any changed clock, verifies original alt, then releases
claims. Failed state restoration retains needed claims for retry. Once state
is confirmed, a retry releases only claims still owned and issues no controls
through an already released interface.

The native queue is explicitly **4x32 OUT packets and 2x32 feedback packets**.
It differs from C7's **4x32 OUT / 2x8 feedback** and is not described as the
same queue. The original `uacrate.c` planner accepts normative feedback only;
its last valid cadence survives rejected feedback. Original quiet stereo
triangle PCM queues 96000 frames, with no PCM dump. Callback work logs raw
packet status/length/feedback bytes in memory; JSON persistence occurs after
measurement and drain. `time.perf_counter_ns()` supplies host monotonic time.
The normal completion deadline is10 seconds.

The callback object, transfers and buffers remain referenced until all
callbacks retire. Cancel is asynchronous; neither failure nor timeout
authorizes freeing lower-owned memory. After a five-second drain delay the
program records a negative, retains every owner and keeps pumping indefinitely.
An external watchdog may identify a stall, but its forced termination is not
successful restoration evidence. All normal cleanup steps are independently
attempted; a close exception retains its native handle/context and skips
`libusb_exit`, while own-process timer-policy restoration still runs.

Own-process timer policy snapshots and clears only IGNORE_TIMER_RESOLUTION,
checks readback, then requests the minimum reported timer period. Successful
Begin is matched by End; all failed attempts are preserved. Original process
policy is restored with readback. No process priority or execution-speed bit
is changed. This is independent of QEMU's existing timer request.

The program preloads the exact supplied libusbK file, verifies its actual
loaded module path via public GetModuleFileName and checks its hash before
and after libusb initialization. It sets LIBUSB_DEBUG=2 only in its own
environment so the existing instrumented622FC DLL emits original raw KISO
records to stderr; the complete stderr file must be retained separately.

## Interpretation and pending physical execution

OUT `actual_length` returned by this Windows libusbK path is synthesized from
requested lengths. It is API accounting, **not measured wire bytes**. Raw
KISO diagnostics and returned packet statuses must be reviewed separately.
The aggregate libusb ISO actual_length field is not used as packet evidence.

The diagnostic criteria (384000 completed-requested bytes, zero packet
errors, at least1600 valid feedback packets, no rejected feedback, host OUT
window1500..2500ms) are this bounded native experiment's policy. They are
not UAC2 class limits. Initial successful ZLP feedback before any valid value
is counted as rejected in this strict experiment; raw bytes/lengths remain
available and that choice must not be confused with a physical packet error.
No feedback watchdog duplicates the guest's200ms watchdog.

Even a future criteria pass will not establish WinMM position, audible
output, fidelity or broad device compatibility. The prepared CLI uses
`--run-physical`, absolute E: output, exact pinned DLLs and SystemExit status
propagation. No physical result or approval to take the device is implied
by the source/build/mock gates above.
