### Source-backed host scheduling experiment plan

The official libusbK [pipe-policy reference](https://libusbk.sourceforge.net/UsbK3/usbk_pipe_management.html)
lists ISO_START_LATENCY policy0x20 (HS default32) and
ISO_ALWAYS_START_ASAP policy0x21 (OUT defaulton). Its detailed prose for
these policies is unfinished, so implementation semantics are checked in
pinned BSD-licensed source rather than invented from names. In
`docs/references/libusbk-4dd2bdd`, drv_policy.c validates latency as a
USHORT and returns/stores it; drv_xfer_iso.c initializes a non-ASAP fresh
pipe from current frame plus latency and advances subsequent HS frame
numbers by `(packetCount >> 3) * framesPerPacket`. Constants, source URLs
and hashes are recorded in that directory's manifest. Only headers and
implementation source were read, not DDK sample code or driver binaries.

QEMU's existing isobufs property defaults to four, isobsize to32. At HS
interval1 that is16ms total OUT ring capacity; QEMU waits for half the
buffers before starting. Adding32ms non-ASAP startup lead with that ring
would exhaust its capacity before completion, so a naive latency switch is
not a valid isolated experiment. The next single-variable experiment first
uses the existing `usb-host,isobufs=16` property under unchanged ASAP policy,
C7 guest SYS, corrected-QEMU candidate and raw2 diagnostic DLL. This is a
bounded X4 host experiment; neither larger buffers nor source review proves
zero packet loss, and no global/released driver policy changes follow.

### CLKSER external clock reference (implemented, 2026-10-22)

(22F1C0CF...7653). Usage: `CLKSER.EXE SECONDS PERIOD_MS REPORT`. The guest

least-squares slopes of guest QPC and GetTick against host arrival time,
plus per-second rates. `launch-clk.ps1` adds the serial socket and uses the
accounting QEMU with `x4clk.events`. `x4run.py` gained `clkstage`,
