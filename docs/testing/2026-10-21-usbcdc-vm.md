# CDC ACM simulation, Windows 2000 and 7 x64, 2026-10-21

An original Python USB-redirection device model exercises the experimental
`USBCDC.INF` with Windows 2000 SP4's in-box `usbser.sys`. This is a simulated
CDC device, not a test of an Arduino, Pico, UART, board reset or bootloader.
No physical USB device is attached to this guest.

**Current regression limit:** the model's full-packet ZLP behavior passes
Windows 7 x64 but remains unresolved on Windows 2000 at the 65-byte echo.
The original 2000 pass below predates that model change. The later regression
section preserves the failures and rejected experiments; there is no current
cross-OS echo pass claim.

## Model and sources

`src/serial/usbcom/acmemu.py` implements a Full Speed CDC ACM control/data
pair, Union and ACM descriptors, interrupt serial-state notifications,
line coding, control-line and break requests, and bounded bulk echo.
It uses Python's standard library and QEMU's existing `usb-redir` device.
The model intentionally uses Uno R3 VID/PID `2341:0043` to exercise the
listed Windows 2000 model. Its product string explicitly says
`CDC ACM echo - SIMULATED device`; no board firmware is reproduced.

The implementation follows protocol facts from USB Chapter 9, CDC ACM,
and SPICE's published
[USB redirection protocol](https://github.com/SPICEorg/usbredir/blob/master/usb-redirection-protocol.txt).
No third-party implementation or driver sample was copied.
`acmtest.py` passes nine host tests covering descriptor bounds, class
requests, ordered echo, cancellation, reset, notifications and malformed
bulk output. Host tests do not substitute for the guest run below.

## Windows 7 x64 follow-up

Fresh `E:\usb-wdm-free\wave1\w7acm.qcow2`, based on `vm/w764.qcow2`,
ran headless with TCG multithread, qemu64, four CPUs, 2048 MiB, std VGA,
PIIX UHCI, no NIC and the same Full Speed ACM model. The advanced boot
menu was explicitly set to **Start Windows Normally**; signature
enforcement was not disabled and no BCD or trust-policy setting changed.
Overlay, exchange, trace and TEMP/TMP files were all on E:.

The native x64 helper builds with `probe64.cmd` using the repository's
WDK 7.1 compiler, Win32 headers/libraries and static CRT. A native helper
is needed for NewDev's documented
[64-bit device-install contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/device-installations-on-64-bit-systems).
Its first unelevated call returned access denied (5). The helper now
embeds an explicit administrator manifest; the normal UAC prompt was
accepted. The legacy `probe.cmd` still builds the 2000/XP helper.
No sample source or third-party implementation was used.

After accepting Windows Security's ordinary unverified-publisher prompt,
`UpdateDriverForPlugAndPlayDevices` returned success/error 0/reboot 0.
The unsigned INF installed as `oem2.inf`, section ACM, service usbser,
provider usb-wdm-free, problem 0, COM3. Open/GetCommState/close passed.
The tested staged INF SHA256 is
`9d01b8120be648e126fc22ff2d3689840895309a1ed426246281fbf2f8e74ee5`.
This confirms this INF-only route using the in-box driver; it does not
test loading an unsigned custom x64 kernel binary or supply a catalog.

Win7 reports `Port_#0001.Hub_#0001` as the location instead of the USB
product name. The helper now dynamically queries the public
`DEVPKEY_Device_BusReportedDeviceDesc` property on newer systems, still
requiring the exact simulated product string before generated writes.
The key and value-type facts come from WDK 7.1 `devpkey.h` and
`devpropdef.h`; no new static SetupAPI import is introduced on 2000/XP.

The first echo run passed 1 and 63 bytes, but the 64-byte read timed out.
The model had returned the 64 data bytes without a following short
packet. A separate ZLP now flushes each completed full-packet echo,
preserving ordering with the next payload. The bounded model queues
packets and ZLPs separately, with 1 MiB of data and 1024 queued entries
as admission limits. Eleven host tests now include full-packet flush
ordering and a final partial packet that needs no extra ZLP.

After replacing the model and reattaching on a new virtual USB port,
Windows reused the staged INF automatically and assigned COM4, problem 0.
All six byte-for-byte echoes passed: 1, 63, 64, 65, 128 and 1537 bytes.
The trace independently records the matching data hashes and separate
zero-length IN responses. It is simulated serial I/O, not a board test.

## Windows 2000 regression and bounded empty-read handling

A fresh `E:\usb-wdm-free\wave2\w2kacmz.qcow2` overlay of `vm/w2k.qcow2`
repeated the PIIX UHCI/Full Speed test under headless TCG, Pentium III without
APIC, ACPI disabled, 256 MiB and no NIC. Its HMP/model ports were localhost
44339/44421; stage, overlays, traces and TEMP/TMP were on E:. No physical USB
device was attached. The current INF installed successfully after the normal
unsigned-package confirmation, with no missing-source prompt or reboot:
usbser, provider usb-wdm-free, `oem0.inf`, ACM, COM3, problem 0.

The model above exposed a negative regression: echoes 1, 63 and 64 passed,
then the 65-byte read returned successfully with zero bytes. The trace
shows this guest submitted 64-byte bulk IN requests. After completing an
exact 64-byte request, the model had queued an extra ZLP; that ZLP satisfied
the next IN, after OUT fragments of 64 plus 1 bytes. No subsequent IN appears
before the probe broke its read loop and closed the port. The trace spans only
milliseconds, so the original report must not be described as a measured
three-second timeout. This is an observed simulated
interaction, not proof that ZLPs are universally invalid for CDC or that the
host would never resume polling under another timing or workload.

An intermediate request-aware model suppressed ZLPs after an exact-length IN.
That passed all six echoes on 2000 after reattachment/INF update (COM4,
problem 0, success/error/reboot 1/0/0), but **failed the 64-byte Win7 echo**.
Both guests' usbredir requests were 64 bytes: their packet-sized requests do
not expose the size of the guest's parent URB. Therefore using that length to
decide whether a flush is needed was invalid and was reverted. Its result is
preserved as a rejected experiment, not the final cross-OS result.

The final model retains a separate flush ZLP after full-packet echoes. The
test helper instead retries successful empty reads, with `Sleep(1)`, at most
4096 read calls, and one fixed three-second deadline per payload. Each blocking
read receives only the remaining timeout; errors are retained, late data does
not extend the deadline, and all bytes must still match the original pattern.
The twelve host protocol tests cover flush ordering at both 512-byte and
64-byte IN request granularity. The actual guest regressions exercise the
Win32 read/timeout logic; there is no separate host-mock Win32 test.

That helper correction alone **did not resolve Windows 2000**: it again passed
1/63/64 and failed 65 with no payload. A single bounded follow-up experiment
coalesced an undelivered flush when new OUT data arrived and omitted a flush
between already buffered stream chunks. Thirteen host tests passed, but the
actual 2000 run still failed at 65: `got=0 error=0 empty=1 calls=2 elapsed=3005 ms`.
The trace shows the ZLP had already been delivered before the next OUT, so
coalescing could not remove it. The helper retried the empty read and exhausted
its remaining deadline; the measured five-millisecond overrun is scheduling/
timeout granularity, not a restarted deadline. This is a blocking negative
result for this model/2000 interaction. No further model iteration was done.

**2026-10-23: the 2000 legs use `--no-flush-zlp`.** The wdm-sweep agent
found that after the simulator's flush zero-length packet following a full
64-byte echo, no further IN request from 2000's `usbser.sys` appeared
during the failing read. A copy of the simulator without that packet passed
the echoes of 1, 63, 64, 65, 128 and 1537 bytes on 2000. `acmemu.py --no-flush-zlp` (off by default; branch `usbcom-nusb`)
sends no flush packet, and 2000's legs use it. The default stays as it is
for the other guests: Windows 7 needs the flush. Whether a real Uno R3 or
Pico firmware sends a zero-length packet after a full-packet echo is a REAL
CHECK for the owner: `usbmon` or an analyser on an echo of exactly 64 bytes.

### Final Windows 7 x64 regression

installed `E:\usb-wdm-free\wave1\w7acm.qcow2` used headless multithread TCG,
qemu64, four CPUs, 2048 MiB, std VGA, PIIX UHCI and no NIC. Start Windows
Normally was explicitly selected; signature enforcement, BCD and trust policy
were not modified. An initial Repair selection was reset while its recovery

used existing `oem2.inf`/ACM/usbser, COM4, problem 0. All six echoes passed,
with no empty application reads and a maximum observed elapsed time of 78 ms

model; both process IDs and both listening ports were verified absent.
