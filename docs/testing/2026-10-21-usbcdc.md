# USB CDC-ACM INF checks, 2026-10-21

`src/serial/usbcom/USBCDC.INF` is an original, unsigned M0 experiment.
It binds Windows' own `usbser.sys`; no Microsoft/vendor sample or INF
template was copied. There is no physical serial board available for this run.
The later [Windows 2000 simulation run](2026-10-21-usbcdc-vm.md)
records installation, COM assignment and generated echo traffic.

## Review and host checks

The model sections retain the intended split: listed Uno R3 whole-device
IDs on every NT target; the whole-device Pico exception in the
undecorated Windows 2000 models only; Pico interface `MI_00` and an ACM
class/subclass match in the XP+ x86 and x64 sections. The class match
does not include CDC Ethernet. The Ports class is the existing system
class; no extra class installer or copied co-installer is introduced.

Microsoft's [Manufacturer section documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/inf-manufacturer-section)
requires undecorated models for pre-XP systems, and describes the
`NTx86`/`NTamd64` selection used here. The associated-service flag is
documented by [INF AddService](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/inf-addservice-directive).
The in-box copy-section reference follows the documented
[usbser reference mechanism](https://learn.microsoft.com/en-us/troubleshoot/windows-client/setup-upgrade-and-drivers/how-to-use-reference-usbser-driver-universal-serial-bus)
and the 2000/XP target-INF readings recorded in the design. This package
uses usbser as its function service, rather than adopting the modem
lower-filter arrangement in that documentation.

The initial build gate matched only recognizable model lines. An extra
line naming a different install section could escape that check, and
service directives were checked globally rather than in their required
sections. The gate now parses every non-comment line, checks the complete
section graph, forbids additional payload/install directives, validates
the exact scoped model set and associated service, verifies string
references and DriverVer syntax, and rejects non-ASCII source text.
It is deliberately a small package policy checker, not a general INF
parser or a replacement for Windows Setup.

```
powershell -NoProfile -ExecutionPolicy Bypass -File src\serial\usbcom\test.ps1
src\serial\usbcom\build.cmd inf free
src\serial\usbcom\build.cmd inf checked
```

Pass: original INF, a case/spacing variation, and fourteen rejected unsafe
mutations. Those include broad CDC matching, a whole-composite Pico entry
on XP+, an unrecognized extra model, additional compatible IDs,
unassociated/boot-start/wrong-binary service changes, foreign co-installer
and file-copy additions, lost AMD64 models, unresolved strings, duplicate
sections, an invalid date and non-ASCII input. Both build flavours stage
ASCII/CRLF with source/build-validator and output hashes in `out/`.

## WDK checker

The installed WDK 7.1 `tools/Chkinf/perl.exe` and `chkinf.bat` were run
against this INF. This reads a kit validation tool, not a kit sample.
Invocation from the repository root:

```
tools\WinDDK71\tools\Chkinf\perl.exe -Itools\WinDDK71\tools\Chkinf tools\WinDDK71\tools\Chkinf\chkinf.bat src\serial\usbcom\USBCDC.INF /O out\serial\usbcom\chkinf
```

ChkInf 2.5 (2002-10-23) exits with failure: two errors, no warnings.

| Diagnostic | Meaning for this experiment |
|---|---|
| E22.1.1081, CatalogFile required for WHQL digital signature | No catalog is generated for this unsigned M0 stage. Signing and package trust remain release gates. |
| E22.1.1017, primary revision must be greater than zero | The experimental DriverVer is `0.0.0.1`; it is not a release version. |

The full checker HTML report is under the git-ignored output folder.
These diagnostics are recorded, not suppressed or described as a checker
pass. The check does not establish the availability of `mdmcpq.inf`'s copy
source on each guest, or that any target's usbser can operate as a
Ports-class function driver. Those are the design's pending M0 experiments.

## Emulation boundary

Stock QEMU's `usb-serial` models an FTDI protocol device, not CDC-ACM;
changing its VID/PID does not supply CDC descriptors, ACM requests or
serial-state notifications. A useful custom model would need a coherent
CDC communication/data interface pair, Union and ACM descriptors,
interrupt notifications, line-coding/control-line/break requests, bulk
echo traffic, unplug/replug and reset behavior. It would be useful for
deterministic Windows binding and I/O regression once implemented, but
would still not establish Uno DTR reset, Pico bootloader behavior or a
real EHCI path. The later run implements that model through QEMU's
usb-redir transport; see the linked run for its scope and results.

The connected Sound Blaster X4's MI_01 interface now passes a real
[XP binding/open check](2026-10-21-uac2-vm.md): usbser, COM3, devnode
problem 0, open/GetCommState/close. No payload or explicit modem-line
change was issued. It does not constitute UART echo or evidence for
Arduino/Pico behavior.
