# Asynchronous synthetic-camera dispatch policy, 2026-10-21

Original portable `uvcflow.c/.h` now executes the proposed worker policy on
top of the actual `uvcown.c` table. It contains no Windows objects, waits,
thread creation, USB calls or class notifications. All operations require
the same caller-held external lock. Request/stream pointers are opaque;
the policy never dereferences class storage.

The known unsafe `uvcrun.c` worker and the tested M0 miniport were not changed
or linked to this core. No RUN-capable SYS or VM/hardware test is claimed.
This implements the next bounded policy/rundown step; Windows integration
remains gated by [the worker design](../design/uvcrun.md).

## Verification

`src\video\uvc98\flowtest.cmd` compiles the actual policy, actual ownership
table and C test harness with VC6 `/W4 /WX /MT`, then runs them:

```
PASS: 361 flow checkpoints, synchronous teardown reentry, delayed admission, reserved shutdown and wrap deadlines
```

The harness exercises actual state transitions and invokes synchronous
notification-style reentry between Finish and Returned. It does not duplicate
the dispatcher in a separate model. Cases include:

- Read-completion reentry that submits STOP, CLOSE or UNINITIALIZE; control
  completion reentry that submits UNINITIALIZE. Reentry enqueues and returns;
  another worker step is blocked until the notification returns.
- Cancellation during unfinished admission, queued PAUSE reads, failed
  mapping, stale admission tokens and cancellation after retirement. No
  frame is generated for a cancelled/mapping-failed ticket.
- CLOSE while a mapper is delayed: teardown remains pending until Ready and
  read retirement, without waiting inside a callback.
- Queue saturation at 24 ordinary reads, emergency stop controls, the
  reserved CLOSE slot and final UNINITIALIZE slot. Every admitted request
  gets one completion, with final device teardown handled separately.
- Serial exhaustion boundaries that retain a generation for CLOSE and final
  UNINITIALIZE; duplicate requests keep their original ownership.
- Ordered SET/GET_STATE, frame deadlines, unrelated control wakeups,
  32-bit clock wrap, no catch-up burst after a long delay, and cancellation
  on a transition below PAUSE.
- Power-down drain, explicit power-up without implicit RUN, flush admission,
  close/reopen policy reset and fail-closed handling of a failed teardown.
- UNINITIALIZE's EXIT cannot be mistaken for an ordinary completion. Final
  completion fails closed unless both worker-join and callback-rundown facts
  are supplied. The harness frees its policy allocation immediately after
  the final handoff, with no return-to-worker step.

No host mock of Windows threads, spin locks, IRPs or STREAM.SYS was used.
Thus these tests establish portable scheduling/ownership transitions, **not
kernel synchronization, callback rundown, stale-address safety or class
extension lifetime**. External join/rundown facts are caller obligations;
the test's true flags are not a usable Windows implementation.
