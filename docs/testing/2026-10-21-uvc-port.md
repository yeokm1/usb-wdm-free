# STREAM.SYS request adapter, 2026-10-21

`uvcport.c/.h` adapts actual public SRB/KS-header/IRP/MDL structures to
`uvcflow`; `uvcportn.c` implements real NT mapping and notification hooks.
Driver-owned bindings use ownership slot/generation, never SRBExtension.
**M0 still excludes these files and rejects RUN.** No USB, VM installation,
Windows98 kernel or full UVC claim follows. Only original code, published
documentation and public headers were used, with no kit samples.

## Buffer and completion contract

[KsProbeStreamIrp](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ks/nf-ks-ksprobestreamirp)
places headers in the system buffer and payload MDLs at Irp.MdlAddress.
[HW_STREAM_REQUEST_BLOCK](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/strmini/ns-strmini-_hw_stream_request_block)
defines NumberOfBuffers, DataBufferArray and Irp. The
[earlier buffer audit](2026-10-21-uvc-stream-buffer-contract.md) explains
why Pio alone is not a worker-address-space guarantee.

This adapter requires one header and one MDL, no chain, full header size,
zero input OptionsFlags, a complete153600-byte frame and MDL coverage of
the advertised FrameExtent. Zero OptionsFlags is a conservative initial
synthetic-mode restriction, not a general KS/UVC validity rule. Header.Data
is never dereferenced or changed. Admission is published before mapping
outside the external lock; even cancelled admission must publish Ready.
Both callback cancellation and captured IRP.Cancel are honored.

[MmGetSystemAddressForMdlSafe](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-mmgetsystemaddressformdlsafe)
maps already locked payload pages and includes the original byte offset.
It is not added twice. The class owns locking, unlocking and freeing.
The mapping API excludes98, so this is an NT2000+ prototype. TimeoutCounter
is zero while queued and restored from TimeoutOriginal when selected,
following the SRB documentation and
[READ_DATA](https://learn.microsoft.com/en-us/windows-hardware/drivers/stream/srb-read-data).

Finish captures owned bindings, retires ownership and clears the binding
before notification. Cancelled mapped headers receive DataUsed0; malformed
headers are not retained or written. A successful fixed frame must be
exactly153600 bytes. Duration is100ms for synthetic10fps; no unproven
TIMEVALID timestamp is supplied. Delivery has no adapter pointer and its
notification hook is its last class-storage access. Returned accesses only
independently retained adapter storage. Final delivery has no Returned;
completion tickets must not be replayed.

`UvPortNtNotify` is for synchronization OFF and completes without Ready.
`UvPortNtSerialNotify` is for synchronization ON inside the class gate. It
uses [CompleteRequestAndMarkQueueReady](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/strmini/nf-strmini-streamclasscompleterequestandmarkqueueready)
as one final handoff. Final UNINITIALIZE instead uses DeviceRequestComplete
only, without reopening admission. The modes must not be mixed.

## Checks

`porttest.cmd`: actual x86 NT hook/adapter objects compile against public
headers; actual adapter/flow/generator with injected mapper/notification
hooks executes **883 checks PASS**. Tests guard the exact frame end, make
SRBExtension inaccessible, supply untrusted Header.Data and nonzero MDL
offset, and cover malformed headers/extents/MDL chains, mapping failure,
delayed admission, cancellation while PAUSED/during mapping, duplicate
admission, timeout restoration and invalid completion byte counts.

Notifications synchronously request CLOSE/UNINITIALIZE and protect all
class objects as no-access before returning. Final notification protects
the entire adapter too. The actual C code survives those host page guards;
this is not real class-callback/IRQL/SMP evidence. A test-development guard
alignment error was fixed before PASS. The launcher rejects all nonzero
results, including negative Windows exception status codes. Parent review
and independent execution also reported883 PASS with no scoped blocker.

`port64.ps1`: WDK7.1 amd64 public-header compile of adapter, NT hooks, flow,
ownership and generator passes with warnings as errors. Compile only;
no x64 driver link/import/runtime claim. Real callback rundown/address
reuse, worker join and exact once-only dispatch still need implementation.
The old unsafe `uvcrun.c` stays unwired.

## Route to a kernel RUN experiment

[Minidriver Synchronization](https://learn.microsoft.com/en-us/windows-hardware/drivers/stream/minidriver-synchronization)
and the [class interface](https://learn.microsoft.com/en-us/windows-hardware/drivers/stream/stream-class-and-minidriver-interface)
document nonreentrant class-serialized callbacks across CPUs. Turning that
off makes ordinary callbacks concurrent at PASSIVE; cancel/timeout/timer
callbacks remain DISPATCH. The
[synchronization guide](https://learn.microsoft.com/en-us/windows-hardware/drivers/stream/synchronization-examples)
places default callbacks at DISPATCH without an ISR; LOW callbacks are
explicitly unsynchronized and HIGH uses the synchronization mechanism.
Moving work to LOW alone therefore does not solve rundown.

The next design retains class serialization for admission, cancel lookup,
retirement and notification. A passive worker only maps/generates retained
jobs. CLOSE/UNINITIALIZE enqueue and return, without waiting inside class
callbacks or completion stacks. A preallocated device-associated work item
joins the exited worker outside that gate. Final completion returns to the
class gate, frees owned resources first and makes notification the last
class access. Caller-owned engine plus admission flag alone is insufficient
with synchronization OFF.

[CallAtNewPriority](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/strmini/nf-strmini-streamclasscallatnewpriority)
permits one routine per stream/device; acknowledgement must not permit
overlapping HIGH callbacks. An alternative
[class timer](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/strmini/nf-strmini-streamclassscheduletimer)
pump must honor its one-timer limit and final non-rearm handoff. It can
continue draining until worker join is observed, then finish under the
class gate. [IoFreeWorkItem](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-iofreeworkitem)
allows freeing a dequeued work item inside its callback; no queued work
item may be freed. A persistent generator uses its own system thread,
not an indefinitely occupied system work item.

The implementation must still prove that callbacks already entering the
class gate cannot outlive final handoff, that Cancel cannot act on a reused
SRB, that LOW initialization has stopped touching engine storage, and that
timer/priority callbacks cannot remain scheduled after final completion.
The SYNTHETIC M1 preflight comes before physical Brio probe/commit, bounded
URBs and complete-payload delivery. USB completions will require a separate
drain; there are none in this adapter. This route is not a completed
callback-rundown proof or project camera capture result.
