# Official USB Video Class references, 2026-10-21

This is a reference acquisition and future verification checklist. There is
no webcam driver under `src/` to audit, and no implementation-conformance,
frame-capture, OS-load or hardware claim follows. The existing
[UVC design](../design/uvc.md) remains a draft.

## Internal-use handling

The 1.1 core and selected payloads grant reproduction/distribution for
internal use only, with no broader intellectual-property license. Their
notices are on PDF page 3. The 1.5 core's internal-use reproduction notice
is on PDF page 4; the selected 1.5 payload notices are on page 3. These
are specification-use permissions, not GPL licenses or patent assurances.
The original notices remain intact. Keep the downloads ignored/local;
do not place them in `free/`, a release archive or a public commit.
This tracked record contains provenance, hashes and original audit notes,
not the specification copies. Consult the documents' complete notices.

## Checks before any implementation claim

- **Function and descriptor boundaries:** validate configuration lengths,
  VC/VS interface association and alternate settings, unit/terminal IDs,
  descriptor references, per-format frame indices, control-bitmap lengths
  and discrete/continuous frame intervals. Reject truncation/overflow and
  preserve sibling audio/HID functions. Use core chapter 3 and both
  payloads' section 3.1; test valid fixtures and guarded malformed inputs.
- **Probe/commit negotiation:** follow the core section 4.3.1.1 operational
  model and its request tables, using the actual advertised UVC revision
  and supported control lengths. Validate returned indices, intervals,
  frame size and payload capacity before commit. Treat failed, short or
  inconsistent responses as errors; do not silently assume a requested
  format was accepted. Check the design's 1.0/1.1/1.5 structure handling
  independently, including any implemented 48-byte 1.5 path.
- **Bandwidth and USB scheduling:** core section 2.4.3.1 covers stream
  bandwidth selection. Verify actual link speed, service interval and
  high-bandwidth transaction capacity; select a sufficient alternate and
  release it at stop. Test isochronous per-packet status, late packets,
  queue depth and cancellation against each intended host stack. Bulk
  payload boundaries need their own tests, not reused isochronous rules.
- **Payload/framing:** core section 2.4.3.3 and tables 2-5/2-6 describe the
  base header and optional fields. Bounds-check declared header length,
  optional PTS/SCR storage and payload size; exercise FID, EOF, ERR, empty
  payloads, missing boundaries and resynchronization. Deliver bounded,
  complete frames and account for dropped/corrupt frames.
- **Uncompressed formats:** section 2.2 of the 1.1 payload lists YUY2 and
  NV12. The 1.5 payload adds I420/M420. Check GUID byte ordering, component
  packing, dimensions, pitch, frame-size arithmetic and color matching;
  a matching GUID alone does not prove correct output pixels. Validate
  captured frames with a consumer on each target OS.
- **MJPEG:** verify the 1.1/1.5 payload-specific descriptor, framing and
  still-image rules. Preserve valid compressed frame boundaries, enforce
  negotiated size limits and test actual decoder compatibility; do not
  describe passthrough as a JPEG decoder implementation.
- **Controls and still capture:** expose only implemented controls and
  supported GET/SET operations, with correct lengths, signedness, ranges
  and units. Test request-error/status behavior and each claimed still
  method. Keep extension units, encoding units and excluded payloads out
  of advertised capabilities until implemented and tested.
- **OS and lifetime contracts:** separately verify the chosen STREAM.SYS/
  KS interfaces on 98 SE, ME and 2000. Test queued-buffer ownership,
  stream transitions, stop, surprise removal, power, reconnect and failure
  recovery with real frames. A downloaded specification, parser pass or
  successful device installation is not evidence of a working webcam.

The download record establishes the official documents are available for
this work. Every implementation, OS and hardware item above remains open.
