# wdmsmoke load and lifetime, 2026-10-21

Experiment of [build.md](../design/build.md) section 6, "Basic WDM
lifetime": does a driver built by this repository's `wdmx86` and `wdm64`
profiles install, start and remove on the tested systems? A
root-enumerated smoke device proves loading and PnP lifetime only, not
USB or NDIS operation, and changes no README cell.

  binaries were built just before that commit, from a working tree at
  `1073da5` holding those same files uncommitted, so `record.txt` says
  `1073da5`, dirty.

  `d0a55084aebb166f0de6e4c1ca77a2416b975298efd82fd629662b989bb1187d`

  (WDK 7.1, WNET amd64).

## Steps

Add New Hardware (98 SE) or Add/Remove Hardware / Add Hardware / Add
legacy hardware (NT): select from a list, System devices, Have Disk
`A:\`, "wdmsmoke test device (not a release)". Then Device Manager's
status for the device, then Remove / Uninstall. Run by the author with
the steps above; results read from the guest screen.

## Observations

- The x86 binary's imports (`NTOSKRNL.EXE`: `DbgPrint`,
  `IoAttachDeviceToDeviceStack`, `IoCreateDevice`, `IoDeleteDevice`,
  `IoDetachDevice`, `IofCallDriver`, `IofCompleteRequest`,
  `KeInitializeEvent`, `KeSetEvent`, `KeWaitForSingleObject`,
  `PoCallDriver`, `PoStartNextPowerIrp`) all resolve on 98 SE's NTKERN
  loader: this is the first guest load-test evidence of build.md section
  5.1 for those routines.
- 2000 shows "Driver Date: Not available" although the INF has
  `DriverVer=10/20/2026`. The smoke INF uses the `$CHICAGO$` signature;
  whether a `$Windows NT$` INF shows the date is checked with the first
  NT package INF.
- Neither binary has a version resource, so Device Manager shows no
  file version. Package builds add one.
- On 7 x64 the test needed signature enforcement disabled at boot, as
  expected for an unsigned x64 driver; the test-signed route of build.md
  section 7 is not exercised here.
- `qemu-system-i386` on this host has no WHPX; WHPX guests run under
  `qemu-system-x86_64`.
