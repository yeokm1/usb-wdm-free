# CDCNET 0.1.0.0: the release-shaped driver, 2026-10-22

The M0/M1 spike of [2026-10-21-cdcnet.md](2026-10-21-cdcnet.md) is replaced
by a driver built to the [Ethernet design](../design/ethernet.md): generic
ECM, NCM and RNDIS, an asynchronous data path, a passive worker, NDIS 5.0
(x86) and NDIS 5.1 (x64) builds, release INFs and test INFs. Nothing is
released; no README cell changes. Every guest leg here is QEMU's Full Speed
`usb-net` model on a UHCI controller: a VM pass, never a "Tested" cell.

## Sources

### Design points as implemented

- **Data path.** 4 bulk-IN transfers (ECM 2048 bytes; NCM the negotiated
  NTB size, at most 16 KiB; RNDIS 16 KiB), one interrupt-IN, one logical
  bulk-OUT. One pump per adapter submits; a completion marks its slot and
  kicks the pump, so inline completions iterate instead of nesting. IRPs
  are allocated per submission and freed by their completion routine;
  data IRPs are never cancelled by pointer: quiesce closes the gate, waits
  for the pump to leave `IoCallDriver`, aborts the pipes, waits for every
  completion (re-aborting every 2 s, never freeing on timeout).
- **Termination.** ECM: frames padded to 60, ZLP as a separate transfer
  when the payload is a `wMaxPacketSize` multiple, before any later
  payload. NCM: one NTB per transfer, ZLP when a multiple and shorter than
  `dwNtbOutMaxSize`. RNDIS: one zero byte after the last message, outside
  `MessageLength`; a ZLP only if the byte would exceed the device's
  transfer limit.
- **Batching.** A batch is sized so its largest case fits: NCM up to
  `wNtbOutMaxDatagrams` (cap 32), RNDIS up to `MaxPacketsPerTransfer`.
- **Worker.** One passive system thread: OID-driven filter/multicast/power,
  reset, error recovery (abort, `RESET_PIPE`, reopen; device-gone after
  repeated failures), RNDIS response fetch and 5 s host keepalives. It sets
  an event before `PsTerminateSystemThread`; the thread object itself is
  waited on only where `IoIsWdmVersionAvailable(1, 0x10)` (2000 and later).
- **Receive.** 64 preallocated packets; `NDIS_STATUS_RESOURCES` below 8
  free, reclaimed using the status saved before indication; halt waits for
  every packet back. A software filter (directed/broadcast/multicast list/
  promiscuous) backs the device filter requests.
- **OIDs.** The set of section 4.5; filter, multicast and `OID_PNP_SET_POWER`
  pend to the worker; `OID_PNP_CAPABILITIES` answers no wake-up. Counters
  are 64-bit when the caller passes 8 bytes. NDIS 5.1 adds the PnP event
  handler (surprise removal) and `NDIS_ATTRIBUTE_SURPRISE_REMOVE_OK`.
- **Protocol choice.** Advanced property "USB protocol" (`Protocol`: 0
  automatic, 1 RNDIS, 2 ECM, 3 NCM), section 10.1's registry switch.
- **Trace flavour.** `build.cmd <profile> trace` writes a line trace to
  QEMU's debug console (port 0xE9). Test-only, never released.

### `CDCRNDIS.INF` on XP and 7 x64 (Windows' own RNDIS driver), via `RNDTEST.INF`

QEMU's usb-net has no RNDIS interface-class id of its own (device class
02), so the test binds the release INF's install sections to `0525:A4A2`.

  Vista/7 section already had them).
- XP after the fix (`RNDTEST.INF`
  `e91559a5b9b994b05fe9f3743949d4e9516b541e82b59c4dfa1682ee67b6704d`):
  installed; `sc qc usb_rndisx`: binary `system32\DRIVERS\usb8023x.sys`,

- 7 x64 (`pnputil -i -a a:\rndtest.inf`): installed, service `usbrndis6`
  created from `netrndis.inf`'s `usbrndis6.ndi`; same: stopped, no
  traffic (ICMP error 1231, network unreachable).
- Cause, in QEMU's own log (`qemu.err` of both runs): when Windows' RNDIS
  driver starts, it sends CLEAR_FEATURE(ENDPOINT_HALT) to endpoints
  0x81, 0x82 and 0x02, and QEMU's usb-net model fails ("failed control

  recovery always ends "device gone" on QEMU. So on QEMU the INF binding
  is verified (driver selected, service and files installed from the
  in-box INF), but Windows' RNDIS data path cannot be: that needs an
  Android phone or other RNDIS hardware (ethernet.md section 7.5's test).

## Not run here, and why

- **CDC-NCM on a guest**: QEMU has no NCM model, and the host rule of
  2026-10-22 (no project program on the host) rules out a host-side USB
  device model over usbredir. NCM rests on the host parser tests above
  until an NCM device (AX88179A/B, a 2.5G dongle) is on the bench.
- **EHCI legs**: QEMU's usb-net is Full Speed only and QEMU's hub is a
  USB 1.1 hub (no transaction translator), so no QEMU leg is an EHCI leg
  (build.md section 8). Owed on hardware for 98 SE (NUSB), 2000, XP, 7.
- **Android tethering / real RNDIS** through `CDCRNDIS.INF` (above).
- **Sleep/resume**: 2000 runs `acpi=off`; 98 SE entered S3 but its resume
  wedges in QEMU's warm-reset path; XP/7 standby not tried.
- **ME, XP x64, Vista, 7 x86**: built, not run (ethernet.md 11.1).
- **Driver Verifier on 2000** (ethernet.md 10.1): not run.
