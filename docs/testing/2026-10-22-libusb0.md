# libusb0: libusb-win32 0.1.12.2 rebuilt for 98 SE / ME, first build, 2026-10-22

The `libusb0` package ([design](../design/libusb.md), section 6) is
imported, changed as the design lists, and built with this repository's
toolchain. **No guest has loaded any of it.** No VM was run for this work
(vCPU share 0). No USB device was touched. Nothing is staged under
`free/`, and no README cell changes. This covers M1's commits 1 to 5 and 7
(design 6.6) as build work only; M0 and every guest check of design 6.7
are still owed.

## Builds and gates (host only)

```
src\generic\libusb0\build.cmd wdmx86|win32|w98 free|checked
```

All six pass at `5c1c71b`. `out\generic\libusb0\w98\free\gate.txt` records:

- **LIBUSB0.SYS**: i386, native, subsystem 4.00, no delay imports or
  ordinals. 35 imports, all in `imports-sys.txt` and declared by the 98 SE
  DDK's `WDM.LIB`/`USBD.LIB`: 34 from NTOSKRNL (the as-is build had 33,
  where design 2.3 counted 34 in upstream's MinGW binary, a difference not
  examined; the `call_usbd()` fix adds `InterlockedExchange`) and
  `USBD.SYS!_USBD_CreateConfigurationRequestEx@8`, which ME's `USBD.SYS`
  export table also lists. All driver sources also compile against the 98
  DDK's own WDM/USB headers. Checked builds add `RtlAssert`.
- **LIBUSB0.DLL**: i386 GUI 4.00 DLL, 56 imports (61 checked), each in
  `imports-dll.txt`, declared by the 98 DDK import library of its module,
  and present in both the 98 SE and the ME export table of that module
  (KERNEL32, ADVAPI32, SETUPAPI, CFGMGR32, MSVCRT). `CM_Get_DevNode_Status`
  comes from CFGMGR32 (cfgmgr32.lib linked before setupapi.lib, as upstream
  `3a902c7` did for 98). No USER32 import is left after commit 3. Exports
  equal `libusb0.def`: 47 names.
- **TESTLIBU.EXE**: console 4.00; 23 imports (MSVCRT in both tables, the
  rest LIBUSB0.DLL exports).
- Version resource 0.1.13.0 in the SYS and DLL.
- **Host tests** (`hosttest.ps1`, `tests/lutest.c` with the DLL's own
  `descriptors.c` and `error.c`): 79 checks, 0 failed. Descriptor parsing,
  a configuration with an IAD, two alternate settings and class descriptors,
  four malformed configurations rejected, the 8-byte then wTotalLength
  fetch, `libusb_request` layout (24 bytes) and the IOCTL codes shared
  with 1.x, the Win32 error mapping.
- **INF**: contract gate (`infgate.ps1`); 15 unsafe mutations rejected
  (`inftest.ps1`).
- **Negative gate checks**: an unlisted SYS import; 1.2.6.0's
  `ExFreePoolWithTag` and `CheckTokenMembership` even when allowlisted; an
  import missing from the ME export table; an ordinal import; a missing DLL
  export. All rejected.
- 0 compiler warnings at /W3 in upstream code (warnings are counted, not
  fatal).

## 98 SE and ME export tables

From the pristine `E:\usb-wdm-free\vm\w98se.qcow2` and `wme.qcow2`, 7-Zip
extracted only `WINDOWS\SYSTEM\{KERNEL32,ADVAPI32,SETUPAPI,CFGMGR32,MSVCRT}.DLL`
(both) and `WINDOWS\SYSTEM32\DRIVERS\USBD.SYS` (ME; the 98 SE image has
none) to `E:\usb-wdm-free\libusb0\exports\98\` and `me\`. MSVC 6.0
`DUMPBIN /EXPORTS` read their export tables; the output was reduced to
ordinal and name in `src/generic/libusb0/exports98/` (each file names its
image and file SHA-256). Nothing else of the binaries was read and none is
checked in. Presence in a table is not proof that a call works.
