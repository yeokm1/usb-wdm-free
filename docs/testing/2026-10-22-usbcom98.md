# usbcom: the 98 SE / ME CDC-ACM driver, first build, 2026-10-22

The Windows 98 SE / ME half of `usbcom` ([design](../design/serial.md),
route B of 5.1.2) is written and built. The build includes `USBCOM.SYS` (WDM), `USBCOM.VXD`
(VCOMM port driver), `USBCOM.INF` and `USBCOMP.INF`, and the pure core has host tests.
**No guest has loaded any of it.** No VM was run for this work (no vCPU
share). No physical serial board was touched. Nothing is staged under
`free/`, and no README cell changes.

## What was written

All of it is original code under `src/serial/usbcom/`:

| File | What |
|---|---|
| `acmcore.c`, `acmcore.h` | OS-independent core, compiled into the SYS, the VxD and the host test. It covers the CDC-ACM descriptor walk (Union, reversed Union, Call Management, "next interface" and combined-interface fallbacks, alternate data settings, several functions per device) and the select-configuration interface list. It also handles line coding, Win16 `CBR_*` mapping and DCB validation, SERIAL_STATE parsing and the MSR/`EV_*`/`CE_*` mapping. It runs the VCOMM `_PortData` queues with XON/XOFF in both directions, null strip, the event character and TransmitCommChar ordering. Finally it parses and chooses the COM number. |
| `ucif.h` | The direct-call interface between the VxD and the SYS, with its calling rules |
| `usbcom.c`, `ucio.c`, `usbcom.h` | `USBCOM.SYS`. It is function driver of the USB device or function PDO, and bus driver for one `USBCOM\COMPORT` PDO per ACM function, named `\Device\UsbCom<COMn>`. Its jobs: selecting the configuration; choosing the COM number from the Enum scan, its own ports and the per-function value it remembers; writing PortName, FriendlyName and SERIALCOMM; running 8 IN, 4 OUT, 1 notify and 1 control URBs from a DPC; the pipe reset work item; surprise removal; and S-IRP to D-IRP power with line state resent on D0 |
| `usbcomv.c`, `usbcomv.def` | `USBCOM.VXD`. The DDB and the control procedure are in C with inline assembly. It has every `_PORTFUNCTIONS` entry, opens the SYS port with `_NtKernCreateFile` and fetches the table with `_NtKernDeviceIoControl`. All SYS calls are made from a global-event callback, never at interrupt time |
| `USBCOM.INF`, `USBCOMP.INF` | 98 INFs. The parent has `DevLoader=*ntkern` and `NTMPDriver=USBCOM.SYS`, and lists the Uno R3, the Pico whole device (owner Q5) and Pico `&MI_00`. The child is Ports with `*vcomm`, `USBCOM.VXD`, `*vcd`, `PortSubClass` 01, serialui and a 28-byte Win32 DCB |
| `build98.ps1`, `gate98.ps1`, `test98.ps1`, `hosttest.ps1`, `acmhost.c`, `imports-wdmx86.txt`, `usbcom.rc` | Build, gates and tests |

`build.cmd` now takes `inf`, `wdmx86`, `vxd9x` and `w98`. The `w98` profile builds
everything, runs every gate and test, and stages one folder.

## Builds and gates (host only)

```
src\serial\usbcom\build.cmd w98 free
src\serial\usbcom\build.cmd w98 checked
src\serial\usbcom\build.cmd wdmx86 free|checked
src\serial\usbcom\build.cmd vxd9x free|checked
src\serial\usbcom\build.cmd inf free|checked
```

All pass. `out\serial\usbcom\w98\free\gate.txt` records:

- **USBCOM.SYS:**
  - It is an x86 native 4.00 image with no delay imports or ordinals.
  - Every import (NTOSKRNL and HAL) is in `imports-wdmx86.txt`, and each name is declared in the 98 DDK's `WDM.H`.
  - The SYS sources also compile `/W3 /WX` against the 98 DDK's own WDM/USB headers.
  - A declaration is not export evidence. Only the guest load test settles that (build.md 5.1).
- **USBCOM.VXD:**
  - It is an LE image whose module type is VxD (38000h), with no imported modules.
  - Export ordinal 1 is a DDB named `USBCOM` with `DDB_Size` 50h.
  - A load-time fixup sets the control procedure.
- **Negative gate checks:** the gate rejects two unlisted imports, an allowlisted import the 98 `WDM.H` lacks (`IoAllocateWorkItem`), and a renamed DDB.
- **98 INFs:**
  - The package contract holds: the sections, the exact model ids, the exact loader values and the copied files.
  - The 28-byte DCB is checked byte by byte.
  - `test98.ps1` rejects 19 unsafe mutations.
- **Host tests:** `acmhost.exe`, built by MSVC 6.0, passes 110 assertions and 200,000 random descriptor mutations. Every descriptor walk runs against a buffer that ends at a `PAGE_NOACCESS` page, so any read past the given length faults the test. Running this unit test on the host is allowed by the owner's host rule of 2026-10-22.

## Toolchain findings (build.md 8 "first implementation must settle")

- **VxD assembler: not needed.** The DDB is a C structure. The control procedure and the event thunks are `__declspec(naked)` C with inline assembly, and the services are called through the 98 DDK `vmm.h` `VxDCall` macro. MSVC 6.0's own `LINK.EXE /VXD` produces the LE image. This means the 2000 DDK `ml.exe` question in design 9 and 14 does not arise.
- **Linker warnings:** `LINK /VXD` warns LNK4078 because code and data are merged into the locked `LCODE` class. That is intended: every port function may run at interrupt time.
- **DDB export name:** the export has to be written `_USBCOM_DDB @1` in the `.def`. The `USBCOM_DDB=_USBCOM_DDB` alias form fails to link with this linker. Windows finds the DDB by ordinal 1, as "Building a Virtual Device" says.
- **`VXD USBCOM DYNAMIC`:** this `.def` statement is accepted by the linker. It is not in the 98 DDK help, and the guest load is what proves it.
- **`ExAllocatePool`:** the 2000 DDK headers turn `ExAllocatePool` into `ExAllocatePoolWithTag`. The 98 `WDM.H` declares both.

## Review

An independent code-review pass found 10 issues before any guest run, and all are fixed:

- notify-pipe resubmit storm;
- pipe reset with transfers still pending, now abort, wait for idle, reset, and clear the halted flag only on success;
- a port started without pipes;
- resume ops queued behind newer ops;
- the `Gone`/`Detach` interleave, now called under the port lock;
- S-IRP to D-IRP mapping missing;
- `PortSetup` freeing the live queue;
- `CE_TXFULL` on a partial write blocking reads;
- a resume DPC after remove;
- ZLP ordering with several OUT transfers.

Two points remain open for M1: the register convention of `VCOMM_Map_Win32DCB_To_Ring0` and `VCOMM_Map_Ring0DCB_To_Win32`, and the argument list of `PortSetModemStatusShadow`. Neither is stated by the headers or the help.

## Guest legs owed (none run)

QEMU has no CDC-ACM model of its own. The legs use this package's `acmemu.py`, the simulated CDC-ACM device ([2026-10-21-usbcdc-vm.md](2026-10-21-usbcdc-vm.md)), attached through QEMU's `usb-redir`. Real boards come in through `usb-host` once the owner's bench is available.

1. **98 SE + `acmemu.py` on PIIX UHCI (M1):**
   - Load: `USBCOM.SYS` loads under NTKERN, which is the export and import evidence; the child devnode appears and `USBCOMP.INF` installs on it.
   - PortName: `COMn` appears in Device Manager. This settles design 5.1.4: does the SYS's hardware-key write come in time for VCOMM, is the Enum scan readable through `ZwOpenKey`, and is `IoOpenDeviceRegistryKey` mapped to the Enum key.
   - VxD: `USBCOM.VXD` loads on open. Record which `DriverControl` argument order VCOMM uses and whether VCOMM checks `PDVersion`.
   - NTKERN: `_NtKernCreateFile` accepts `\Device\UsbComCOMn`.
   - Data: HyperTerminal round-trip, plus the 7.1 timeout cases through VCOMM.
   - `Contention=*vcd` versus empty.
2. **98 SE + `acmemu.py`:** PurgeComm, EscapeCommFunction order, break, XON/XOFF and SERIAL_STATE events, using a Win32 test tool still to be written in this package.
3. **98 SE:** pull while open with HyperTerminal holding the port (7.9), standby/resume (7.10), two simulated devices at once.
4. **98 SE under xHCI98 (`nec-usb-xhci`) and NUSB:** the `&MI_00` path.
5. **ME:** a "Built, not tested" leg only (README policy).
6. **Real hardware (owner's bench):**
   - Uno R3: DTR reset on open, 921600 baud.
   - Pico: whole-device binding on the 98 SE in-box stack, 1200-baud touch, 1 Mbit/s throughput.
   - EHCI legs behind a High Speed hub (NUSB).
7. **NT `USBCDC.INF` (not re-run here):**
   - Its display strings changed today, so its hash changed. The earlier 2000/7 x64 simulation results were recorded with the old hash.
   - XP SP3 with `acmemu.py`: binding and the composite Pico `MI_00`.
   - The open 2000 ZLP regression of the simulated model.

## Board list and manual model (owner decisions, 2026-10-22)

Q6 is accepted, and the generic model is manual-only (`docs/design/serial.md` 8 and 13).

- **The list.** `src/serial/usbcom/boardids.txt` lists 170 ids beyond the Uno R3 and the Pico, 12 of them single-function. Each line names its source; the header records each source's repository, the branch head at fetch time and the fetched file's SHA-256.
- **Sources.** All were fetched to `E:\usb-wdm-free\usbcom\pids\` as data, and only the ids were read:
  - Arduino AVR `boards.txt` (Leonardo and Micro, with their bootloaders);
  - SparkFun AVR `boards.txt`;
  - arduino-esp32 `boards.txt` (303A and 239A boards);
  - Adafruit SAMD and nRF52 `boards.txt`;
  - arduino-pico `boards.txt` (239A boards);
  - linux-usb.org `usb.ids` 2026.06.26 (STM32 VCP `0483:5740`);
  - WCH's own GPL Linux driver id table (CH9102 `1A86:55D4`).
- **Generated sections.** `geninf.ps1` writes the model sections of `USBCOM.INF` and `USBCDC.INF` from the list. `validate.ps1` and `gate98.ps1` derive the exact expected lines (string and id, in order) from the same file.
- **Manual id.** The manual-only entry uses `USBCOM\MANUAL_CDC_ACM`, which no device reports.
- **New mutation tests.** These are rejected:
  - a composite board listed whole on XP;
  - a changed board PID;
  - a broadened or dropped manual id;
  - a swapped display string.
  The mutation tests now total 23 for the 98 INFs and 18 for `USBCDC.INF`.
- **Builds.** `build.cmd w98 free|checked` and `inf free|checked` pass.
- **Owed.**
  - Whether the Caterina bootloaders, the STM32 VCP and the CH9102 really are single-function (device class 02) is an inference. It is read on real devices in M0/M2.
  - Whether a large model list installs on 98 SE and 2000 is part of guest leg 1.
