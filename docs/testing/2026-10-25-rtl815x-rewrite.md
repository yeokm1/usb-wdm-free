# rtl815x chip core rewrite, 2026-10-25

Owner, 2026-10-25: the repository moves from GPL-2.0-only to
GPL-2.0-or-later, and the rtl815x chip core, the only code adapted from a
GPL-2.0-only source (Linux `drivers/net/usb/r8152.c`), is rewritten
rather than kept as an exception. This record is the check of that
rewrite. Not a release, not "Tested": no RTL8152/8153 is on the bench, so
every run here is against a register model or the simulator.

## What changed

- `src/net/rtl815x/rtlchip.c` and `rtlchip.h`, written anew (ethernet.md
  section 6.4): the register facts of the adapted core (chip ids, register
  addresses, bit values, the order of reads, writes and sleeps, and which
  values read back decide a path) as tables of register steps run by one
  interpreter, with hooks for the steps that depend on a value read back.
  Every register and bit has this project's own name (`MR_` MAC space,
  `UR_` USB space, `PR_` PHY, `SR_` PHY SRAM); no code, function names,
  comments or structure of `r8152.c` are kept. `r8152.c` itself was not
  opened while writing; the facts were taken from the adapted core and
  its traces.
- `NET_PARAMS.Version` is now the chip id (`5c10` for an RTL8153 with id
  5C10) instead of Linux's `RTL_VER_` number; the driver trace reads
  "chip start: 0, version 5c10".
- `rtltest.c`, `rtlemu.py`, `rtlsimtest.py`: the new names; version checks
  by chip id.

## Trace comparison (old core against new)

A one-off harness (not kept in the repository) linked the old core
(`rtlchip.c` at `646b51a`) and the new one, each with `netchip.c`, to the
same register-file model (`rtltest.c`'s, plus knobs) and wrote every
control request (direction, wValue, wIndex, length, data written or
read), every sleep and every result of every `NET_CHIP` call.

Each run is a whole life: Start; SetFilter with the link down; Link and
Poll down; link up at 1000 full; Poll and Link; SetFilter promiscuous,
all-multicast, 40 groups, 7 groups, directed and broadcast; Link at 100
half and 10 full; SetMac; link down; Link at 10 half; Suspend; Resume;
Link up; SetFilter; Stop; Suspend after Stop.

| Set | Runs |
|---|---|
| Chip ids 4C00, 4C10, 4800, 5C00, 5C10, 5C20, 5C30, 6000, 6010, 6400 and 7020 (an RTL8156, refused) | each at Full, High and SuperSpeed |
| Model variants, each at High and SuperSpeed per id | burst size 0; 32-pin package bit; power-cut status stuck; PHY state power-down, external-init, never ready; PHY patch never granted; FIFOs, transmitter, MAC reset, autoload, link list, ALDPS bit, PHY reset each stuck; efuse 0x1234, 0xffff and bit 16; saw counter 0x123 and 0x4001; link up at start; MAC address zero; the first 1, 2 or 3 requests failing |
| A failure at every request | each id at High Speed (5394 failure points); for these only the request count, the final status, `Timeouts` and a hash of the whole register model are written |
| Pure functions | chip id of all 65536 id words; 300 random multicast hashes; 3000 random receive transfers; 64 transmit headers; 64 interrupt reports; 312 one-bit corruptions of a vendor configuration descriptor |

The old core's version number is written as the chip id it stands for,
so both cores' outputs use the same field. Result: 561 logged lives
(973100 control requests and 714650 sleeps) plus the 5394 failure runs;
the two outputs (36.8 MB each) are byte-identical, apart from one
diagnostic difference: the core's internal `Timeouts` count (bounded waits that ran
out) is identical in every run without a failure (0 to 10 in the
stuck-bit variants), but after an injected I/O failure the new core no
longer counts the waits cut short by it (the old one counted 1 to 3).
