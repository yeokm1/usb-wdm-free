# Release 0.1.2: the licence move, 2026-10-26

Owner decision 2026-10-26: re-release every package whose released files
carried the old licence text (GPL-2.0-only), after the repository moved to
GPL-2.0-or-later (owner, 2026-10-25; commits `e7e1b3c`, `253f8d7`,
`65d09eb`), and reword the third-party licence statements (`435ec69`).
Branch `relicense`, from `rel-011` (`646b51a`).

## What changed

- Versions (`877757c`, `d91c3cb`): `DriverVer=10/26/2026,0.1.2.0` in the INFs of
  `uac2`, `usbmidi`, `cdcnet`, `usbcom`, `usbflop`, `uvc98`, `ax88179` and
  `rtl815x`; `noaud`, on its own numbering, 1.0.1.0. `rtl815x.sys`, rebuilt
  with its rewritten chip core, is 0.1.2.0 in `rtl815x.rc`
  ([its own record](2026-10-26-rtl815x-0.1.2.md)). `usbflop`'s and
  CamCheck's `README.TXT` name 0.1.2; CamCheck's `NOTICE.TXT` states the
  new licence.
- `release\0.1.2.psd1`: 0.1.1's definition, with the re-released INFs
  and texts taken from the tree (`tree:src\...`, `tree:release\...`), as
  0.1.0's re-cut did for `cdcnet`, `usbmidi`'s generated INFs from its
  build, and `rtl815x` from its build. Every other driver image keeps its
  0.1.1 bytes (`tree:free\...`): the code of those drivers did not
  change (the relabel touched comments only), and the six x64 images are
  the owner's signed 0.1.0 images. `xpad98` and `libusb0` are unchanged
  (their files already said GPL-2.0-or-later).

## The release operation

`release\release.ps1 -Definition release\0.1.2.psd1 -NonFree
<usb-wdm-nonfree 418dda1, v1.0.0 plus a README commit>`: PASS, 85 files
under `free\`. Against 0.1.1: 40 files change. Their only changed lines
are the SPDX line and `DriverVer` (34 INFs), the version and licence
lines of `usbflop`'s two `README.TXT` files and CamCheck's `README.TXT`
and `NOTICE.TXT`, and the two `RTL815X.SYS` files. Every other file,
the six signed x64 images among them (the release operation checked
each one's signature and SHA-1 image digest again), has 0.1.1's bytes.
`STAGE.TXT` changes only in `rtl815x`'s note; `SHA256.TXT` is rewritten.
No hardware id is staged twice on one system over this set and
usb-wdm-nonfree's.

## Signing

Under this repository's signing policy (build.md section 7, item 4: an
embedded test signature on x64 images, no catalog for a package with an
image of its own), 0.1.2 needs no new signature: the x64 folders that change
(`audio/uac2/wxp-x64`, `wv-8-x64`; `audio/usbmidi/wxp-x64`, `wv-8-x64`;
`net/cdcnet/wxp-x64`, `wv-7-x64`) carry the owner's signed 0.1.0 images,
byte for byte, and only their INFs changed, which no signature covers;
`hid/xpad98/wxp-x64` and `wv-x64` do not change. The tag waits for the
owner.
