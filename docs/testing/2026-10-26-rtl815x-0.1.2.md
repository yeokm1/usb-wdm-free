## The RTL8152 leg with TCP/IP bound

The rewrite record's RTL8152 leg sent no frame: no protocol was bound to
the new adapter. This leg ran 0.1.2 builds of `RTL815X.SYS` (copied over
the installed one) on the same 98 SE guest (kit
`E:\usb-wdm-free-vm\relicense`, xHCI98 3.1.0.0, 1 vCPU, TCG), with
`rtlemu.py --chip 8152` (id 4C10, `0BDA:8152`) on the xHCI port:

- Network control panel: the "Realtek RTL8152 USB Fast Ethernet
  (RTL815X)" adapter had no binding (its Bindings tab listed no protocol),
  and adding TCP/IP bound nothing. Six adapters had TCP/IP bound (three
  "CDCNET test" adapters left from earlier legs, the Dial-Up Adapter and
  two RTL8153 instances). After one CDCNET test adapter was removed,
  adding Microsoft TCP/IP bound it to the RTL8152 adapter ("TCP/IP ->
  Realtek RTL8152 USB Fast Ethernet"). Restart, as Windows asked.
- After the restart, the simulated RTL8152 plugged in: DHCP (the
  simulator's log), ARP, then `ping -n 8 -l 1472 192.168.77.1` 8/8,
  0 % loss; removal clean. That run had the build of `877757c`
  (`71bdf3d4...`), whose version strings still read 0.1.0.0; the
  released image (`61298001...`) then ran the same way on the same
  guest: `ping -n 8 -l 1472` 8/8, removal clean.

So the missing frames came with the guest's network configuration: with
six TCP/IP bindings in place, a seventh adapter got none. What limit 98 SE
sets there was not looked up; it was seen once on this guest.
