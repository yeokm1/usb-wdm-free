# uac2 on Windows 2000: STOP 0x1E in usbhub20.sys when uac2 starts on a device already enumerated, 2026-10-31

The second finding of the seek legs (`2026-10-31-uac2-seek.md`, "Two
findings on 2000"): changing the "USB Audio Device" (Windows' own
`usbaudio.sys`) to `uac2` stopped Windows 2000. Read on branch
`w45-uacswap` from `348756d`. Development legs in QEMU (TCG) with the
simulator, not "Tested".

## Result

The stop is not in `uac2`'s code. Windows 2000 stops in `usbhub20.sys`
while that driver handles a Plug and Play query which PortCls sends to the
device's PDO from inside `PcAddAdapterDevice`, the first call `uac2`'s
AddDevice routine makes. It happens when the PDO had already been started
once and removed while the device stayed attached: a driver change in
Device Manager (Update Driver from `usbaudio` to `uac2`), and Disable then
Enable of a working `uac2`. The first start on a freshly enumerated
device (plugged in, or present at boot) does not stop. The query was
seen in `uac2`'s starts only; no other PortCls driver was run on this
device, so whether every PortCls driver's start meets it was not read.
`uac2` itself sends nothing before the stop. No change to `uac2` that
would keep the query from the hub driver was tried (one would be a device
object of `uac2`'s own between PortCls's and the PDO).

- Drivers: `uac2` 0.1.5.0 as released (`uac2wdm.sys` `528f2ad0...`,

| B3 | (a) | Update Driver, Have Disk, `uac2` 0.1.5.0 | STOP 0x1E (C0000005, F20C9D75, 0, 44) in `usbhub20.sys`, as the seek legs' two |
| B4 | (a) | Update Driver to an INF that installs no driver | no stop |
| B3' | (a) | Update Driver to the port-0xE9 build | port 0xE9: `DriverEntry`, then the line before `PcAddAdapterDevice`, never the line after it; the same STOP |
| k6a | (a) | the same, stack read at the stop | the same STOP; the call chain below |
| k6b | (b) | Disable (no stop), then Enable | the same STOP, the same call chain |
| k6c | (a) | Update Driver to 0.1.5.0 with `Reboot` in `[UAC2.NT]` | no stop; "The hardware you installed will not work until you restart your computer"; after a cold start `uac2` works and `UACSEEK wo s16 48000 3 2000 p` plays (PASS, no stale block) |

The call chain at the stop, the same in k6a and k6b, from the bottom of
the stack: the Plug and Play worker thread (`ntoskrnl.exe`) calls
`uac2wdm.sys`'s AddDevice; that calls `PcAddAdapterDevice`
(`portcls.sys`); PortCls calls `IofCallDriver` with an
`IRP_MJ_PNP`/`IRP_MN_QUERY_INTERFACE` (interface type
`4747B320-62CE-11CF-A5D6-28DB04C10000`, size 0x1C, version 0x100, status
preset `STATUS_NOT_SUPPORTED`) addressed to the PDO
(`\Driver\usbhub20`, its attached device the new `uac2wdm` FDO); inside
`usbhub20.sys`'s dispatch the read of address 0x44 faults. `uac2` had
not touched the device: its extension is set up after
`PcAddAdapterDevice` returns, and no request of its own had been sent.

The earlier record said the stop came during the file copy; it comes
after the copy, when the device is restarted on the new driver. The
`ks.sys` damage the seek legs saw (`c000026c` at the next boot) is the
stop's consequence: the copy had not reached the disk.

## What can be done

- Install `uac2` before the device is first plugged in (`UACCI.INF`, as
  `README.md` and the 0.1.5 release notes give), so the first start is
  on a fresh PDO and `usbaudio` never binds. Not affected.
- If `usbaudio` already has the device: uninstall the "USB Audio Device"
  (B1, no stop), unplug, put `uac2`'s folder on `DevicePath` and install
  `UACCI.INF` (README "Installing"), plug in again. Not run as a
  whole leg here.
- Disable and Enable of `uac2` on 2000: avoid; Enable itself stops. To
  stop using the device, unplug it.
- An INF `Reboot` directive in a 2000-only install section (k6c) avoided
  the stop on Update Driver: 2000 left the device for the restart instead
  of restarting it on the new driver. It does not cover Enable. Whether
  to ship it is the owner's decision (a 2000-only `[Models.NTx86]` with
  XP and later moved to `[Models.NTx86.5.1]`, and a restart prompt at
  every 2000 install).

## Not covered

- 2000 under xHCI98 or under Windows' UHCI only: not run.
- A real PC and a real device: not run.
- Who cleared the PDO's state that the query reaches was not read; only
  the stop, the stack and the IRP were.
