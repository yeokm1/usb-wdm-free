# Release 0.1.7: usbprn 0.1.0.0, 2026-11-01

Owner, 2026-11-01: a new release once `usbprn` is done. 0.1.6 plus
`usbprn` 0.1.0.0 (`docs/design/printing.md`): on Windows 98 SE the driver
`USBPRN.SYS`, the port monitor `USBPRNMN.DLL` and `USBPRN.INF`; on ME
`USBPRNME.INF`, which binds ME's own `usbprint.sys`. Every other file is
0.1.6's. [Release notes](../release-notes.md), section "Release 0.1.7".
The legs are in [usbprn-legs](2026-10-31-usbprn-legs.md); this record is
the release operation.

## The build results

- `usbprn` (`src\print\usbprn\build.cmd free`): built at `a0c7a48`, tree
  clean, every gate and the host tests PASS (`PASS.TXT`). Both images
  read FileVersion 0.1.0.0; both INFs carry `DriverVer`
  10/31/2026,0.1.0.0. The release ran at `891d709` (the definition), and
  the release operation's freshness check found no `usbprn` source change
  between the two.
- The legs ran the build of `0477e4f`, whose `usbprn` sources are the
  same as `a0c7a48`'s. The two INFs are byte for byte the legs' INFs.
  `USBPRN.SYS` and `USBPRNMN.DLL` differ from the legs' images
  (`DBB195A8...`, `2C175137...`) only in the link time stamps (the PE
  header's and, in the DLL, the export directory's) and the PE checksum:
  4 and 6 bytes, no other byte.
- `usbprn` is x86 only, unsigned: nothing in this release was signed.
  Not rebuilt, because unchanged since `v0.1.6`: every other package.
  `uac2`'s x86 files come from the tree, and every x64 image is an
  earlier release's signed image, taken as a `strip:` entry.

## The release operation

`release\release.ps1 -Definition release\0.1.7.psd1 -X64Dir
E:\usb-wdm-free-wt\x64-017 -Thumbprint
E6A2749B78E9E4074260CF79972A57EEB6E76C0A -Certificate
usb-wdm-free-test.cer -NonFree <usb-wdm-nonfree 4345b06>`. `-X64Dir`
holds the tree's 12 released x64 images, each under the name of its
`x64:` entry (`uac2.wxp-x64.uac2wdm.sys` and so on), unchanged.

- `-Check`: "release: checks PASS; -Check, nothing published".
- The release: "release: PASS; free\, STAGE.TXT and SHA256.TXT written
  (105 files)": 0.1.6's 101 and `usbprn`'s 4.
- Every x64 image read signed by `E6A2749B...` (0.1.4's certificate), no
  timestamp, and matched its stripped form outside the checksum and the
  certificate table.
- `USBPRNME.INF` loads `usbprint.sys`, declared as Windows' own (it is on
  ME's disk after setup; the M0 leg). With `-NonFree`, no hardware id is
  staged twice on any system: usb-wdm-nonfree stages no printer class
  INF.
- Changed under `free/`: `free/print/usbprn/` is new; no other file
  changed. `STAGE.TXT` gains `usbprn`'s `PACKAGE` line and two `STAGE`
  lines, `USBPRN.INF` on 98 SE and `USBPRNME.INF` on ME; no other line
  changed. `SHA256.TXT` gains the four `usbprn` lines.
- The ME INF is `STAGE`, not `COPY`: ME has no INF of its own for a USB
  printer, so a staged `USBPRNME.INF` is the only way the first plug gets
  a driver; staging it is what the M0 leg did (the INF in ME's INF
  folder, then the printer bound by itself and printed). It names only
  the interface ids `USB\Class_07&SubClass_01&Prot_01` and `_02`, and a
  vendor's VID/PID INF outranks it.
