# uac2 build 26: each device shown by its USB product string, 2026-11-05

The change is design record section 21 (`docs/design/uac2.md`). These
are development legs in QEMU (TCG) with the simulator, not "Tested";
no real device was used.

## Rig

- Emulator: the usb4-emu QEMU fork `cb36497` (`usb-redir`), q35. The
  simulator `uacemu.py` is plugged on `qemu-xhci` port 1, under xHCI98.
  `--product TEXT` sets its `iProduct` string, and `--no-product` sets
  `iProduct` to 0.
- Build 26 at `d69a452`: `uac2wdm.sys` x64 `da9095e4...`, x86
  `ed443d6f...`. On each system it was copied over the installed file
  with no device plugged, and compared by `fc`.
- XP x64 SP2: a fresh overlay of an XP x64 disk with xHCI98 (the
  3.4.1.0 tree's amd64 build `8b962d4e`) and `uac2` installed.
- 7 x86 SP1: an overlay of a 7 x86 disk with xHCI98 3.4.0.0 and `uac2`
  build 24 installed.
- 98 SE: an overlay of a 98 SE disk with xHCI98 3.4.0.0 and `uac2`
  build 24 installed (its `cx31993` and `hs24` devices already
  present).
- What was read:
  - `UACWAV list`: every `waveOutGetDevCaps` / `waveInGetDevCaps`
    `szPname`.
  - The sound control panel, by screenshot: XP's Sounds and Audio
    Devices, Audio tab; 7's Sound, Playback tab; 98 SE's Multimedia,
    Audio tab.
  - The driver key's `Uac2Name`, `Uac2NameStatus` and
    `Uac2NameDevnode`.

- **`szPname` on 7.** It is the endpoint's name, "Headphones (...)",

  previous run's export. The names above are `szPname` and the
  screenshots.

## Why the devnode on Vista+ (the 7 runs before `d69a452`)

The first build 26 (`66a1612` and its review fix) wrote only the
interfaces' `FriendlyName`. On XP x64 every row above already showed
the product string.

On 7, the interface keys held the new names (`reg query` of
`DeviceClasses\{6994AD04-...}`, e.g. `#Wave\Device Parameters`
FriendlyName "CX31993 Headphone DAC"). The panel still showed "4- UAC2
USB audio (experiment)", and every Render endpoint's stored adapter
name (`MMDevices\...\Properties` `{b3f8fa53-0004-438e-9003-51a46e139bfc},6`)
was the INF's.

Then the `3302:12C3` devnode's `FriendlyName` was set to "Devnode Named
DAC" by hand, run as SYSTEM through `schtasks`. After a replug,
`szPname` was "Headphones (Devnode Named DAC)". So `d69a452` writes the
devnode's `FriendlyName` on Vista and later, and the rows above are
that build.

## Not covered

- Vista, 8, 8.1, 2000, XP x86 and ME. Each shares a measured system's
  path (design 21.2).
- Device Manager's name on 7.
- VLC was not run.
- An `iProduct` read that hangs or stalls on a real bus. The simulator
  always answers; the 5 s cancel is the transport's (design 21.3).
- Real devices. Test kits find a real device by its product name
  through `UACWAV_NAME`.
