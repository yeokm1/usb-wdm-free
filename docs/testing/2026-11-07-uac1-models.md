# UAC 1.0 device models against Windows' own usbaudio, 2026-11-07

xHCI98 Phase 47: `uac1` (a UAC 1.0 driver for usb-wdm-free 0.1.9) needs
device models to be tested against, and the owner's rule is that every
model is first run under a driver written without it. For UAC 1.0 that
driver is Windows' own `usbaudio.sys`: XP SP3 x86, Windows 10 22H2 x64
and 98 SE. This record adds `src/audio/uac2/uac1emu.py` (thirteen profiles,
two of them replays of the owner's devices, three negative fixtures for
uac1's G3), runs each profile under those drivers, compares two of them
with the real devices under the same drivers, and notes where the model
was changed.

These are development legs in QEMU (TCG), not "Tested".

## The model

`uac1emu.py` subclasses `uacemu.py`'s usbredir device (hello, endpoint
info, iso streams, the capture sine, feedback scheduling, the received and
rendered peaks, packet gaps) and adds what is UAC 1.0: the descriptors
(USB Audio 1.0 4.3 to 4.6, Type I of the Formats document), the class
requests (5.2: SET_CUR, GET_CUR/MIN/MAX/RES to Feature, Mixer and Selector
Units; SAMPLING_FREQ_CONTROL and PITCH_CONTROL to the endpoint), a rate per
endpoint, and stream validation. A separate file keeps uacemu's fourteen
UAC 2.0 profiles and their record untouched; one module would have mixed
two request sets keyed on the same bmRequestType values. The `dual`
profile switches between the two classes by configuration, which the
subclass makes simple: configuration 2 is uacemu's own `hs24` function.

Stream validation, per OUT endpoint: frames per packet against the
nominal (the rate times the service period; for an asynchronous endpoint
the rate its feedback reports), packets more than one frame off it,
zero-length packets, packets that are not whole frames or exceed
wMaxPacketSize (counted, not fatal), and a modelled device FIFO
(`--fifo-ms`, default 4 ms) filled by the packets and drained by the
nominal, whose underruns and overruns are counted. Each stream ends with
an `ostream_verdict` log line.

| Profile | Speed | Shape |
|---|---|---|

`--speed` moves a built Full Speed profile to High Speed; `--strict-volume`
refuses an off-step or out-of-range volume instead of rounding and
clamping it; `--fb-ppm`, `--fb-zero-every`, `--fb-stop-after` (uacemu's),
`--fb-at-refresh` and `--fb-lead-empty` shape the feedback. Built ids are
FFFF:0300 to FFFF:0307 and FFFF:030A to FFFF:030C; the replays keep their own ids (`--vid`/`--pid`
change them). Host tests: `uac1simtest.py`, 42 tests (every profile, the
requests, the validation, the replays' answers, the socket handshake).

**UAC 1.0 and 2.0 on one device.** No real device is known that offers
UAC 1.0 on one alternate and UAC 2.0 on another of the same interface: the
AudioControl interface's protocol fixes the function's class, and its
streaming interfaces follow it. Real dual-mode devices use two
configurations (a recorder interface lists configuration 1 as UAC 1.0, 48
kHz at most, and configuration 2 as UAC 2.0; Linux and Windows both take
configuration 1), or a speed switch (UAC 1.0 at Full Speed, 2.0 at High
Speed), or a hardware switch and re-enumeration. `dual` models the first
form.

## The real devices

The owner's Sound Blaster Play! 2 (041E:323D) and Logi USB Headset
(046D:0A64), bound to WinUSB on the host by the owner, were each marked in
use in `E:\xhci98-vm\devices.txt`, passed to the XP and 10 guests by QEMU
`usb-host`, and released when done. Only Windows' own drivers in the
guests talked to them. `testdata/play2` holds the Play! 2's device,
configuration and HID report descriptors; `testdata/logi0a64` (captured
2026-10-21) gains the Logi's HID report; both READMEs list the class
answers each unit gave, which the replays return.

Play! 2: four interfaces; capture (interface 1) stereo 16-bit 44.1/48 kHz
ASYNC IN; playback (interface 2) the same, ASYNC OUT with a 3-byte sync
endpoint `0x83`, bRefresh 5 (32 ms); a sidetone path through Mixer Unit 9
(no programmable crosspoint); HID. It stalls GET_CUR of Selector Unit 12
and of every Mixer Unit 9 crosspoint, the device qualifier and string
`0xEE`.

Logi: playback ADAPTIVE 2 channels at 8 to 192 kHz in 768-byte packets
behind a 1-channel input terminal, mono capture 8 to 48 kHz, Feature Units
with a master entry only, sidetone through Mixer Unit 12 (every crosspoint
stalls), string 6 "Sidetone", a 142-byte HID report.

## QEMU and a rarely polled sync endpoint

A UAC 1.0 sync endpoint is polled every 2^bRefresh ms. QEMU's
`usb-redir` (`hw/usb/redirect.c`) starts an iso IN stream on the first
poll and answers polls with zero bytes until 60 packets (60 ms at Full
Speed) are buffered. For the Play! 2's endpoint (bRefresh 5) the model's
log shows QEMU stopping and restarting that stream about 25 times a
second (95 restarts in 4 s of one XP stream), each restart starting the
prefill again, so no poll ever found a value: 109 of 109 on XP, 266 of
266 on 10. Why QEMU stops it was not traced. The real device behind
`usb-host` fared the same (250 of 252 empty on 10). With
bRefresh 2 (`async`) 10 received 1826 values in 2021 polls. The model
therefore sends a feedback value every frame (`--fb-at-refresh` for every
2^bRefresh ms), and `--refresh N` overrides a replay's bRefresh as a rig
option.

XP SP3's `usbaudio.sys` does not survive an empty feedback packet: with
`async` (bRefresh 2) 18 of XP's 24 polls were still empty at the stream
starts, XP sent one 396-byte packet (wMaxPacketSize 294), and stopped on
0x7F; with `play2` it sent 1028 to 1676-byte packets, or stopped on 0x7F.
So XP's asynchronous-OUT path cannot be exercised under QEMU, with a real
device or a model; `--fb-lead-empty N` reproduces the condition for a
driver under test, which must treat a zero-length feedback packet as no
news.

## Changes to the model from these legs

- Mono Feature Units first had a master entry only; UAC 1.0 4.3.2.5 wants
  one per channel of the cluster. The built profiles were fixed (a host
  test checks every unit). The Logi's own units have the master entry
  only; its replay keeps that.
- Feedback was first sent every 2^bRefresh ms, as a host polls; under
  QEMU that never reached the guest (above). Now every frame by default.
- A replay's identity: serial index 0, the qualifier and string `0xEE`
  stall as the real units do, string 6 of the Logi answered.
- Volume SET_CUR between steps is rounded to a step, not refused: XP sent
  `DA81` to the Logi and the unit took it.
- Review: a High Speed sync endpoint is 4 bytes (16.16); configuration 2
  of `dual` keeps the device's own descriptors; the command line takes the
  aliases; float samples are clamped before conversion (an infinity
  ended the model).
- uac1's G3 negative fixtures `pcm8`, `float`, `adsrc` added (agent uac1's
  request); the existing profiles are byte for byte unchanged (checked).
- Float samples that are NaN, infinite or past full scale are counted, for
  what XP sent.
