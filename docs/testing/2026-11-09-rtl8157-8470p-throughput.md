# rtl815x 0.2.1.0 throughput on a real PC at High Speed, 2026-11-09

The owner's HP EliteBook 8470p under Windows XP x64 SP2, a real Realtek
RTL8157 (`0BDA:8157`) on the right-side connector (Windows' own EHCI, High
Speed), cabled to another computer. Measured with xHCI98's TBSPEED (one
TCP connection, 20 s runs) against a `TBSPEED -s -w 256` server.

| Direction, socket buffer | rtl815x 0.2.1.0 | trial build (w48-r15 `39b6d1d`) |
|---|---|---|
| XP x64 sending, Windows' default buffer | 18.3 Mbit/s | 18.7 Mbit/s |
| XP x64 sending, 256 KB | 196.5 Mbit/s | 195.2 Mbit/s |
| XP x64 receiving, default buffer | 295.3 Mbit/s | 132.8 Mbit/s (one run) |
| XP x64 receiving, 256 KB | 309.6 Mbit/s | 318.7 Mbit/s |

The owner's earlier iperf 2.0.8 run (XP x64 sending, its 8 KB default
window) gave 69.3 Mbit/s.

**Reading.** Sending is limited by the TCP window XP x64 gives a socket by
default, not by the driver: with a 256 KB buffer the same driver sends about
196 Mbit/s and receives about 310 Mbit/s, near what High Speed carries. The
trial build (eight bulk-OUT and ten bulk-IN transfers, a send completed when
its frame is in a submitted transfer) changed neither direction measurably,
and its one default-buffer receive run was lower, possibly noise after a
replug. The trial build is not merged (owner, 2026-11-09); rtl815x 0.2.1.0
stays as it is.
