## The `0FE6:9702` composite

CoreChips' SR9700 with a driver disc: interface 0 a CD-ROM (class 08,
SCSI, bulk-only), the Ethernet on interface 1 with device class 0, so
Windows' composite driver splits it. `sremu.py --composite` (`7c1142b`,
`8fd3e92`) models it: interface 0 answers its descriptors with no
endpoints (no disc is modelled), the Ethernet endpoints belong to
interface 1 in usb-redir's endpoint information, and both interfaces
answer `SET_INTERFACE` 0. `sr9simtest.py` reads the descriptors and the
interface split.

XP SP3 under Windows' own EHCI (the NT matrix's harness copied to
`E:\xhci98-vm\p48\wdmb\nt`, stock QEMU 11.1.0, set
`sr9702-xp-win-11091248`): `usbccgp` split the device; `MI_01` bound
`sr9700f` ("CoreChips SR9700 USB Ethernet with a driver disc (SR9700F)",
from `SR9700F.INF`'s `USB\VID_0FE6&PID_9702&MI_01`); `MI_00` bound
Windows' `USBSTOR` and stopped with code 10 (the model gives it no
endpoints; a real disc's interface would start). DHCP address, pings of
32, 1472 and 4000 bytes and TCP: PASS on the first plug, after a replug
and after a restart.

(The earlier sets `sr9702-xp-win-11091155` and `sr9700-vx86-win-11091210`
passed the first plug and the replug and failed the restart: they ran
with `ax7emu.py` before `5eb6700`, whose link-up logging assumed a PHY
that `sremu.py`'s chip lacks, so the simulator stopped at a link event.
Void; the sets above are their reruns.)
