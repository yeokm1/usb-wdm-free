# uac2 and uac1: the drivers' new names, 2026-11-09

The owner's decision of 2026-11-09: the audio drivers' names lose
"(experiment)". `uac2`'s devices are named "USB Audio 2.0 (uac2)" (a
later endpoint pair " 2" to " 4") and its install disk "usb-wdm-free uac2
driver"; `uac1`'s "USB Audio 1.0 (uac1)" and "usb-wdm-free uac1 driver".
The driver's own copy of the name (`NameFallback`, what a device without
a usable product string is named; [uac2.md](../design/uac2.md) 21.3)
changed with them. Commit `8d7411c`. These legs read the new names where
each system shows them. Development legs in QEMU (TCG) with the
simulator, not a release and not "Tested".

  against `uac1wdm.inf`.

## For the release

- The x64 `uac2wdm.sys` changed (its name string): the release needs the
  owner's signature on it, for `wxp-x64` and `wv-8-x64` alike. No
  catalog ships with these INFs, so nothing else is signed; on 8 and 8.1
  x64 a test catalog is made per leg, as before.
- The INFs keep their `DriverVer` (`uac2` 0.1.10.0, `uac1` 0.1.0.1): a
  release that carries the rename sets its own version.
- A system that already has the driver keeps the old name on a device
  until the driver is updated from the new INF; 98 SE keeps one copy of
  the INF in `INF\OTHER` ([uac2-swap](2026-11-06-uac2-swap.md)).
