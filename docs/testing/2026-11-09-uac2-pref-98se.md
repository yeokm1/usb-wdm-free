# uac2 0.1.9 on 98 SE and ME: the preferred devices across starts, 2026-11-09

The open item "47.11 `uac2`: Windows' preferred device on a real device
swap" ([open items](open-items.md)) left, among the parts that need no
real device, "on 98 SE under xHCI98 the recording choice that moved after
the restart, cause not settled" (step 8 of
[uac2-swap](2026-11-06-uac2-swap.md): the recording choice D read as A
after the cold start that followed an update of another device). These
legs read where 98 SE keeps the preferred devices and how a start changes
them, with two simulated `uac2` devices attached in different orders and
times. Development legs in QEMU (TCG) with the simulator, not a release
and not "Tested".

**Outcome.** 98 SE keeps two pairs of values in
`HKEY_CURRENT_USER\Software\Microsoft\Multimedia\Sound Mapper`: the
choice in force (`Playback`, `Record`) and the user's choice
(`UserPlayback`, `UserRecord`). At a start, and when a device arrives,
the choice in force is set from the user's choice when that device is
present; while it is absent, another present device is put in force and
the user's choice is kept. So a choice read as moved after a start is
what 98 SE shows when the chosen device was not there yet; it comes back
when the device is there (at its plug, or at the next start). This is
98 SE's own behaviour and does not depend on `uac2` or its INF. It is the
likely cause of step 8's reading, whose `User` values were not read then.
ME falls back and returns the same way for the device in force; the
values written to its key did not hold its choice as on 98 SE (below).

## Rig

- **Driver:** `uac2` 0.1.9 as released (`free/audio/uac2/w98se-me`):
  `uac2wdm.sys` `b3c4d555d59236f199a207091a32c4a32eb91fe1dd46fb36a20e0f0e7daab0c9`,
  `uac2wdm.inf` `87236d1a45e51e7514b6d6ba23e8f996c39a777d1a137845f4b0522dcd18daa4`
  (`SetupPreferredAudioDevices` 2), staged on `DevicePath` before the
  first plug.
- **Emulator:** the usb4-emu fork `cb36497` (`3e7f6bf5...`), `pc`
  machine, one vCPU; both devices on `qemu-xhci`.
- **Base:** the 9x matrix's `w98x` (98 SE, NUSB 3.3, xHCI98 3.4.2.0
  `3990e17d`), read-only, a fresh overlay per leg.
- **Devices:** `uacemu.py --profile hs24` (High Speed, duplex) under
  product ids `02A1` and `02A4` and product names "UAC2 A" and "UAC2 D"
  (`--product`), at `bf92407`.
- **Readings:** after each step, `REGEDIT /E` of the Sound Mapper key and
  `UACWAV list` (the wave devices in WinMM's order), read on COM1.
- **Choices** were written to the key with `REGEDIT /S` (the Multimedia
  panel's recording list cannot be reached from the keyboard): in leg
  `p1` only `Playback` and `Record`, in leg `p2` both pairs, as the
  readings showed a choice is kept.
- "At boot": attached right after QEMU starts, before 98 SE runs; "after
  the desktop": attached once the guest answers.

## Leg `pref-w98-xh-p1`: the choice in force only

| Step | Playback / UserPlayback | Record / UserRecord |
|---|---|---|
| A installed, cold start, A at boot | A / A | A / A |
| D installed (new id; the INF's `SetupPreferredAudioDevices`) | D / D | D / D |
| cold start, A then D at boot | D / D | D / D |
| `Playback` set to A, `Record` left D (the `User` values left D) | A / D | D / D |
| c1: cold start, A then D at boot | D / D | D / D |
| c2: cold start, D then A at boot | D / D | D / D |
| c4: cold start, A at boot, D after the desktop | D / D | D / D |
| c5, c7: cold start, A then D at boot | D / D | D / D |
| c6: cold start, D at boot, A after the desktop | D / D | D / D |

A change of `Playback` alone did not survive the next start: 98 SE set it
again from `UserPlayback` (c1). (c3, both devices after the desktop, was
lost to 98 SE's first-plug wedge, task 36.41.)

## Leg `pref2-w98-xh-p2`: the user's choice

| Step | Playback / UserPlayback | Record / UserRecord | Wave devices (in, out) |
|---|---|---|---|
| A installed, cold start | A / A | A / A | A; A |
| D installed, cold start, A then D at boot | D / D | D / D | D, A; D, A |
| both pairs set: playback A, recording D | A / A | D / D | D, A; D, A |
| d1: cold start, A then D at boot | A / A | D / D | A, D; A, D |
| d2: cold start, **A only** at boot | A / A | **A** / D | A; A |
| d2, then D plugged | A / A | D / D | A, D; A, D |
| d3: cold start, A then D at boot | A / A | D / D | A, D; A, D |
| d4: cold start, **D only** at boot | **D** / A | D / D | D; D |
| d4, then A plugged | A / A | D / D | A, D; A, D |
| d5: cold start, A then D at boot | A / A | D / D | A, D; A, D |

- Both pairs written: the choice survived every start with both devices
  present (d1, d3, d5, each with A attached before D).
- With the recording device absent at the start (d2) the recording in
  force became A while `UserRecord` kept D; plugging D put D back at
  once. The same for playback with A absent (d4).
- After each start and arrival read here, WinMM listed the playback
  device in force first (wave device 0); right after the key was written,
  before a start, the order was still the old one.

## ME (leg `pref2-me-xh-p3`)

The same leg on the 9x matrix's `mex` base (ME with xHCI98 3.4.2.0
`3990e17d`), both devices on `qemu-xhci`:

| Step | Playback / UserPlayback | Record / UserRecord |
|---|---|---|
| A installed, cold start | A / - | A / - |
| D installed, cold start | D / - | D / - |
| both pairs set: playback A, recording D | A / A | D / D |
| e1: cold start, A then D at boot | **D** / A | D / D |
| e2: cold start, A only at boot | A / A | **A** / D |
| e2, then D plugged | D / A | D / D |
| e3: cold start, A then D | D / A | D / D |
| e4: cold start, D only at boot; then A plugged | D / A | D / D |
| e5: cold start, A then D | D / A | D / D |

- ME wrote no `User` values of its own ("-": absent), and at the next
  start it put D back in force for playback although the written values
  said A; so the values written here do not set ME's choice as they set
  98 SE's. What ME's Multimedia panel writes was not read (the panel was
  not used).
- The fallback is the same as 98 SE's: with D absent at the start (e2) A
  was put in force, and D came back when it was plugged.

## Not run

- 2000 (no prepared image with `uac2` and two devices in this kit); the
  real devices, and the Multimedia panel itself writing the choice
  (written here as 98 SE's readings showed it stored; on ME those values
  did not hold).
- A Device Manager update of a device that is not the preferred one
  (step 8 itself): the harness cannot drive that wizard; the mechanism
  above needs only the chosen device to be late at the start.
