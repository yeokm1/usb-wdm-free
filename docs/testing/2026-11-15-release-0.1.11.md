# Release 0.1.11: the device names, prepared 2026-11-15

0.1.10 plus the device names of
[wdm-free-names](2026-11-15-wdm-free-names.md) (owner, 2026-11-15):
every name the drivers show carries "(wdm-free)", and a sound or MIDI
name too long for it loses the maker's name first. This record is the
preparation and the release operation's checks before the owner signs.
[Release notes](../release-notes.md), section "Release 0.1.11".

## Versions

The owner's rule for this release: a driver whose image changed gets a
new file version; every INF that changed gets a new `DriverVer` (dated
11/15/2026), also where only its strings changed, so that 98 SE and XP
take the update. The images of the INF-only packages stay 0.1.10's byte
for byte (and so their file versions), as the definition takes them
from the tree.

## Checks

- `release.ps1 -Definition release\0.1.11.psd1 -Part x86 -Certificate
  release\usb-wdm-free-test-sha1.cer -NonFree <usb-wdm-nonfree> -Check`:
  "release: checks PASS". Against `free\` the x86 tree differs in the
  INFs of every package but the co-installer's, `noaud`'s `README.TXT`,
  and the images of `uac2`, `uac1`, `usbmidi`, `USBCOM.SYS` and
  `libusb0` (`LIBUSB0.SYS`, `.DLL`, `.LIB`, `.A`, `TESTLIBU.EXE`); every
  other file, CamCheck included, is 0.1.10's. 46 lines of `STAGE.TXT`
  change: the notes of the changed INFs, which begin with their new
  version.
- The same run without `-Part x86`, with `-X64Dir` holding the four
  unsigned x64 images and the thirteen released x64 images of 0.1.10:
  8 failures, exactly the four unsigned `uac2wdm.sys` and `usbmidi.sys`
  ("x64 driver is not signed", "signed and unsigned images do not line
  up"). The thirteen released images passed against their `strip:`
  entries. `free\` is not written until the owner's signed run.

## What the owner signs

Four files, the two unsigned x64 images above, each under the two names
of its folders: `uac2.wxp-x64.uac2wdm.sys`, `uac2.wv-8-x64.uac2wdm.sys`,
`usbmidi.wxp-x64.usbmidi.sys`, `usbmidi.wv-8-x64.usbmidi.sys`; with the
test certificate of 0.1.9 and 0.1.10, `CN=usb-wdm-free test signing
SHA-1 (not trusted)`, thumbprint `7A3C6E6289EC46E6E128D87BB54E87196B824959`
(record [sha1-cert](2026-11-06-sha1-cert.md)), as the earlier releases:
the WDK 7.1 SignTool, an embedded signature, SHA-1, `/nph`, no timestamp
([release 0.1.8](2026-11-05-release-0.1.8.md), [release
0.1.0](2026-10-24-release-0.1.0.md)). The other thirteen x64 images are
0.1.10's released, signed files and are not signed again. Then the
release operation runs with `-X64Dir` and writes `free\`, `STAGE.TXT` and
`SHA256.TXT`.
